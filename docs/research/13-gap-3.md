## 1. Executive summary for implementers

1. **No lattice can have Z-set addition as its merge.** An abelian group whose operation is idempotent is
   the trivial group ({0},+) ([WR] §3, Strawman 2). An abelian group whose update is inflationary is also trivial
   (Strawman 1). A ring whose × is idempotent is a product of Boolean rings, and its + (XOR) is not monotone in
   the × order ([WR] App. B). So signed diffs can **never** travel as lattice deltas. The law harness
   (TEST-083) must reject every attempt.
2. **The fix is two layers** ([WR] §3): group or ring semantics at the *query-processing layer*, a semilattice at
   the *network layer*, and a translation layer between them.
   - The lattice is a grow-only set of **update IDs**: a UUID in §3.1, or a (replica, local clock) pair in §3.2.
   - A payload is applied to the local group exactly when its ID is new.
   - Commutativity of + means **no ordering metadata is needed**.
   - Associativity means a sender can sum many updates into one payload.
3. **Four concrete wrappers follow** (§6), each with different costs:
   - W1, the UUID set ([WR] §3.1);
   - W2, dots with acks and resends ([WR] §3.2);
   - W3, cumulative-per-origin, the Node-ID-Map / PN-counter trick ([DISS] §4.2.1). The *group inverse* lets it
     apply `C′ − C` on each advance [ours].
   - W4, OnceTree ([DISS] ch. 4), which gives O(degree) metadata for any associative-commutative aggregate.
4. **Every DBSP-incrementalizable view can be replicated coordination-free, in the SEC sense.** Replicas that
   have applied the same set of updates have equal input Z-sets, so they have equal views. The ring's × plays no
   role in replication ([WR] §4). **But none of those views can ever be declared final.** This is the
   "inverse curse" (FT Thm 18, Cor 20): if every state can return to an identity state, a non-constant query has
   no free-termination state.
5. **Free termination** (FT Def 3): state *s* is final for query *Q* iff every state reachable from *s* gives
   the same *Q*. It is the **completeness** dual of CALM's **soundness** property.
   - (Q, I) is coordination-free correct iff I is an FT state (Thm 22).
   - Positive coordination-freeness, which is CALM's notion, holds iff Q is monotone. Negative
     coordination-freeness holds iff Q is antitone (Thm 24–25).
   - Non-monotone queries can still terminate freely *on particular inputs*.
6. **What the runtime can conclude:**
   - Boolean threshold queries over inflationary state are final exactly at or above their threshold line
     (Prop 13). A threshold query never becomes final for an instance where the answer stays false.
   - With a join-semilattice state space, all FT states agree (Prop 15). Two replicas can therefore never
     finalize different answers.
   - Seals (the `All()` relation, §5.2) *make* states final, and producing them is the coordination.
7. **Deciding FT exactly** is linear time for finite state spaces (Prop 26, an SCC algorithm). For first-order or
   Datalog¬ queries over open relational state it is undecidable in general (§9.2, our reduction from
   Trakhtenbrot). We therefore implement:
   - a **static classifier** (ANA-120);
   - a sound **runtime lower/upper-bound ("Kleene") finality test** (ANA-121) [ours];
   - exact SCC-based FT for declared finite-state components (ANA-122).
8. **OnceTree** achieves idempotence with O(1) state per node for any associative-commutative aggregate, over a
   spanning tree, with O(log n) propagation.
   - The evaluation reports about 0.5 MB per node at 2⁸ replicas, against tens to hundreds of MB for
     PN-counters ([DISS] §4.7.2).
   - It gives SEC, but not causal consistency.
   - We adopt it as a P2 transport option.
9. **Retractions are negative weights** ([WR] §2.2, §5).
   - The user-visible multiset clamps weights at 0.
   - A client-side guard ("ignore a delete when the observable count is 0") recovers "causal multiset
     semantics".
   - Concurrent deletes can still drive a count to −1.
   - Dolan proves this trade-off is unavoidable: every undoable CRDT is a tuple of counters.
10. **Emmy** ([DISS] ch. 6) and Hydro PR #3198 show how UDF algebraic properties get verified.
    - Emmy uses Kani bounded model checking, which proved about 83–99% of properties on real closures, plus
      fuzzing for unbounded types. Its rule is **0% false positives**.
    - Hydro now has Verus-checked commutativity obligations.
    - Hydro's type system already encodes our key rule: **a fold over an `AtLeastOnce` stream needs an
      idempotence proof** (`ValidIdempotenceFor<ExactlyOnce> for NotProved` only).

## 2. Algebraic background as the sources define it

From [DISS] §2.1, [WR] App. A and [FT] §3–4. We use these definitions verbatim in our spec.

- **Commutative:** x∘y = y∘x. **Associative:** (x∘y)∘z = x∘(y∘z). **Idempotent** (binary): x∘x = x. For a unary
  function, idempotent means f(f(x)) = f(x).
- **Invertible:** for all x there is y with x∘y = 0. Inverse functions satisfy f⁻¹(f(x)) = x.
- **Monotone:** x ≤ y ⇒ f(x) ≤ f(y). **Inflationary:** ∀x f(x) ≥ x ([DISS] §2.1.5). The two are independent:
  x/2 on the positive reals is monotone but not inflationary, and |x| on ℤ is inflationary but not monotone.
- **Semilattice:** ⊔ is associative, commutative and idempotent. It induces the order a ⊔ b = b ⇒ a ≤ b.
- **Monoid:** associative with an identity 0. **Group:** a monoid with inverses. **Abelian group:** a
  commutative group.
- **Semiring (+,×):** + is associative and commutative with an identity; × is associative with an identity;
  × distributes over + on both sides. **Ring:** a semiring whose + has inverses.
- **Ring homomorphism:** φ(a+b)=φ(a)+φ(b), φ(ab)=φ(a)φ(b), φ(1)=1, φ(0)=0.

**Which network nondeterminism each merge property absorbs** ([WR] §2.1; [FT] App. B; [DISS] §2.2.1):
- associativity absorbs *batching*;
- commutativity absorbs *reordering and interleaving*;
- idempotence absorbs *duplication and retries*, and also duplicates arriving along multiple gossip paths
  ([DISS] §2.1.3).

The design principle we adopt: **if a payload type lacks a property, the channel must supply that property.**
- Missing idempotence: supply exactly-once through a wrapper.
- Missing commutativity: supply ordering, which is coordination.
- Missing associativity: forbid sender-side batching.

**State-based CRDT** ([FT] §3.1; [DISS] §2.2.1): a state D with `update: D×L→D`, which must be inflationary in
the merge order; `merge: D×D→D`, which must be associative, commutative and idempotent; and `query: D→R`. The
four examples used throughout:
- **G-Set:** union.
- **2P-Set:** INSERTS and DELETES, both grow-only; query INSERTS − DELETES.
- **G-Counter:** map replica → ℕ, pointwise max; query Σ.
- **PN-Counter:** map replica → (ℕ×ℕ), pointwise max; query Σ(P−N).

**DBSP model** ([WR] §2.2; R09 §5.3):
- State and updates are **Z-sets**, maps from tuples to ℤ with finite support.
- Update is abelian-group addition. A deletion is an insertion with weight −1. A modification is a deletion
  followed by an insertion.
- A **linear** operator satisfies f(a+b) = f(a)+f(b), i.e. it is a group homomorphism, and is incremental by
  f(Δ) + f(old). Selection and projection are linear, and linearity composes.
- A **bilinear** operator distributes over + in each argument. Join is the standard example, costing
  |Δ|×N instead of N².
- "Relational algebra, Datalog, grouping, and aggregation" are all incrementalizable this way ([WR] §2.2,
  citing DBSP).

## 3. *Wrapping Rings in Lattices* in full ([WR]; [DISS] ch. 5)

### 3.1 The two impossibility results (§3), with proofs

**Strawman 1: the CRDT update is the group update.**
- Assume + is inflationary: ∀x,y: x+y ≥ x. The PaPoC text says "monotonically non-decreasing"; the dissertation
  rewords it as "inflationary".
- The printed chain of inequalities is slightly garbled. In clean form, inflationarity gives both
  0 = x + (−x) ≥ x and x = 0 + x ≥ 0. So x = 0 by antisymmetry.
- The paper concludes: "So x = −x = 0 for every x in the group", i.e. **the group is trivial.**

**Strawman 2: the CRDT merge is the group update.**
- Merge must be idempotent: x + x = x. Adding −x to both sides gives x = 0.
- So **only ({0},+) has an idempotent group operation.**

**Appendix B: rings.**
- + cannot be a CRDT operation (by the argument above), so the only candidate is ×.
- If × is idempotent, the textbook theorem applies: a ring in which every element is ×-idempotent decomposes,
  via φ(x) = (xe, x(1−e)), into copies of the Boolean ring ({0,1}, XOR, AND) = ℤ/2ℤ.
- XOR is not monotone in the order induced by × (the paper notes 1 ≤ 0 under that order), so + cannot be the
  update either.

**Engineering consequence.** A declaration like `lattice ZSet { merge = + }` is **mathematically unsound**, and
TEST-083 will find a counterexample immediately (x ⊔ x ≠ x). LANG-120 must reject group types as lattices. The
only legal pattern is the two-layer one below.

### 3.2 The layered idea (§3)

"The role of the lattice is to allow us to replicate state while being protected against nondeterminism of
computer networks. **The network plays no role in our data modification (+) or query evaluation.**" The
analogy the paper uses is TCP: "at a lower layer we propagate updates around the system wrapped up in a nice
robust semi-lattice. We call this construction a 'lattice-wrapper'" (Fig. 1).

In Fig. 1:
- blue arrows are incoming Z-set updates;
- green diamonds are lattice wrappers;
- red dotted arrows are CRDT merges broadcast to the replicas;
- a purple arrow converts a merge into a group update inside the wrapper;
- the red dot at the center is the materialized view.

### 3.3 The "very simple construction" (§3.1, Listing 1, verbatim from [DISS] Listing 5.1)

```rust
let mut my_group = Group::Zset::new();
let mut my_inbox = Lattice::Set::new();

fn processUpdate(&mut self, update_payload: &Zset) {
    self.my_group.apply(update_payload);
    let update_id = Uuid::new_v4();
    let update_wrapper = (update_id, update_payload);

    my_outbox.insert(update_wrapper);
    neighbors.send(my_outbox);
}

fn receiveUpdate(&mut self, (incoming_uuid, incoming_zset): (Uuid, &Zset)) {
    if (!my_inbox.contains(incoming_uuid)) {
        self.my_group.apply(incoming_zset);
        my_inbox.insert(incoming_uuid);
    }
}
```

What the listing and its prose establish:
- **The lattice state is "a set of updateIDs"**, merged by union. The outbox is itself a grow-only set of
  `(id, payload)` pairs, and `neighbors.send(my_outbox)` resends the *whole* outbox. That is state-based gossip,
  so it tolerates loss and duplication without acks, at O(history) cost.
- **No FIFO or causal order is enforced.** "It is only a couple extra lines of code … (we wait until we see the
  updates in-order from the sender) … but because our update operation is an abelian group it is commutative, so
  we don't need to bother with any extra metadata … eventual consistency and linearizability give the same
  results at the application level for abelian group-based and ring-based applications." The last claim is
  about *application-level* results of commutative updates. It does not say reads are linearizable.
- **Cost:** "each node [must] keep track of the list of every updateID they have ever seen."

### 3.4 The "performant construction" (§3.2)

- Each replica has a unique ID and "a local logical clock that it increments each time it receives a local
  update to the group". The update ID is the pair **(uniqueID, localLogicalClock)**.
- The replica sends the resulting map element `(id ↦ Z-set payload)` to the others.
- The receiver's merge checks whether that pair is already in its processed set.
- Per-node clock values "can be stored in heavily compressed representations as they are long runs of
  contiguous integer values".
- Receivers **acknowledge**. The sender garbage-collects a payload once *every* replica has acknowledged it, and
  **re-sends to nodes that haven't acknowledged after a fixed time interval**.
- The claimed metadata is "proportional to the number of replicas on average rather than the number of updates".
- The design is "similar to the delta-CRDT lattice wrapper [van der Linde et al.] and familiar in networking
  literature as a part of the TCP protocol". I did not read the cited paper.

**Not specified in [WR]** (our additions are in §6.2):
- crash and restart of the sender, including reuse of clock values and loss of the unacked buffer;
- the exact encoding of the compressed ID set;
- what an acknowledgement contains;
- membership changes, which affect "every other replica has acknowledged".

### 3.5 Rings (§4)

Query optimizers exploit semiring axioms: join associativity, commutativity of selection, and distributivity of
filters over join. IVM uses **rings** because + needs inverses, since + *is* the update. "The × operator in the
ring is analogous to join." Moving from group to ring "doesn't need to change our lattice wrapper at all". The
ring structure only enables **local** plan rewrites.

**For us:** ring laws belong to the optimizer (ENG-080..093). Replication cares only about the group
(+, 0, −) of the *input* updates.

### 3.6 Deletion semantics (§5)

- **2P-Set.** Neither insert nor delete is naturally commutative or idempotent on a single node: "insert A;
  delete A" and "delete A; insert A" differ. So the 2P-Set "treat[s] all deletions as if they occur after all
  insertions". An element can be inserted at most once and deleted at most once ("tombstoning").
- **OR-Set.** Causality fixes the sequential case, but "for concurrent writes ambiguity … remains, so a user
  must pick whether to default to deletes first or inserts first".
- **Z-set.** Insert and delete increment and decrement a weight.
  - "For user-facing multiset semantics we may **display all negative multiplicities as 0**."
  - The CRDT view is that each tuple carries a PN-counter column for its multiplicity.
  - Full commutativity breaks a user who deletes at count 0 expecting it to stay 0, and it re-creates the
    insert/delete-order anomaly.
  - **Fix: the client ignores deletions when its *observable count* is 0.** "The 'observable count at the
    client' is exactly the updates that occur causally before the new update at that client."
  - **Remaining anomaly:** two clients both see count 1 and delete concurrently, giving −1. "The best semantics
    … is application specific." The result "avoids tombstoning and achieves something that could reasonably be
    called **causal multiset semantics**."

### 3.7 Related-work claims that bear on design (§7)

- **Op-based CRDTs** "delegate the semi-lattice properties to a networking layer" and need only an associative,
  commutative update (a commutative monoid). Some op-based CRDTs, such as counters, are already abelian groups
  and so "amenable to DBSP-style incrementalization". Which operators and queries over commutative *monoids*
  can be incrementalized automatically is left open. "The definitions of linearity and bilinearity are the same
  for commutative monoids."
- **δ-CRDTs** make network cost proportional to the update batch, as IVM does for compute.
- **Novelty claim:** "the first work to explicitly connect the algebraic view of incremental view maintenance
  … and the algebraic view of eventual consistency."
- **Future work (§6):** extend the Hydro `lattices` crate, whose fuzz-tests check lattice laws, "to support
  rings, groups, fields, and semi-rings". This matches our TEST-083 and TEST-087.

## 4. OnceTree: distributed idempotence in O(1) space ([DISS] ch. 4)

This chapter is unpublished outside the dissertation. It is the "algebraic upgrade" from an abelian
**semigroup** (associative and commutative) to a **semilattice**: it adds the *I* to AC code (§4.8.2). No
inverse is needed.

### 4.1 Problem and prior tricks (§4.2)

- **Vector Clock Idempotence Trick.** Each node stamps messages with a monotonically increasing sequence number,
  and the receiver drops duplicates per sender. This costs O(n) per node and O(n²) in total. A footnote adds:
  out-of-order messages can be buffered to emulate in-order delivery, as TCP does.
- **Node ID Map Trick.** This one is state-based. Each node gossips `serverId ⇒ (clock, value)` for every
  server, and the merge keeps the entry with the higher clock per key. "To display the overall count, we sum
  all the counter values in the map." It is idempotent because every entry has a single writer. It costs O(n)
  per node. This is exactly how G- and PN-counters work.

### 4.2 The protocol (§4.3)

**System model:**
- nodes have unique IDs and mailboxes;
- the network is "best-effort with retries": out of order, possibly duplicated, eventually delivered to live
  nodes, never corrupted;
- nodes are organized into a **logical tree overlay** built by a spanning-tree algorithm (Perlman).

**Three ingredients:**
1. **Controlled flooding over the tree.** "When I receive a message from my neighbor, I forward it to all of my
   neighbors except the sender." Every (source, destination) pair then has exactly one path.
2. **A Node ID Map restricted to neighbors.** `[neighborID ⇒ (clock, value)]`, merged by max clock.
3. **Aggregation instead of forwarding.** Neighbor *j* is sent the aggregate of the local value and every
   *other* neighbor's value, never *j*'s own. Sending *j*'s value back would create a second path.

**Algorithm 1 (verbatim):**

```
crdt OnceTree-Replica
  state_local, state_i∈(0..|neighbors|) ← (0, ⊥_aggregation)
  timestamp ← 0
  merge merge_i(v)
    if state_i,clock < v_clock then
      state_i ← v
  gossip
    timestamp ← timestamp + 1
    for i ← (0..|neighbors|) do
      agg ← state_local,value
      for j ← (0..|neighbors|) do
        if i ≠ j then
          agg ← agg + state_j,value
      send_i ← agg
  operation localUpdate(update)
    state_local ← state_local + update
  query
    agg ← state_local,value
    for i ← (0..|neighbors|) do
      agg ← agg + state_i,value
    return agg
```

The pseudocode sends only `agg`, but `merge` compares `v_clock`. The message must therefore be
`(timestamp, agg)`: "we use a local logical clock that increments whenever a local variable is changed in order
to ensure our merge operation (max(incomingTime, currentTime)) ignores duplicate or out of order messages"
(§4.3.2).

Other points from §4.3:
- **Values are cumulative, not deltas.** "The values being sent are not '+1' … but the full sum of local
  states." The latest message from a neighbor therefore supersedes the earlier ones, which is why loss is
  tolerated when gossip is periodic.
- **Update and aggregate can be different functions**, as long as each is associative and commutative (§4.3.2).
- **Space.** It is O(1) only if the aggregate's output size is O(1). Any AC query converges, but "the space
  usage will only be constant if the size of the query output is constant" (§4.3.4).

### 4.3 Correctness (§4.4)

**Assumptions:**
- a spanning tree;
- update and aggregate are associative and commutative;
- best-effort delivery with retries;
- no Byzantine nodes;
- the proofs assume no failures.

**Definitions.**
- EC = (1) every update delivered at one correct replica is eventually delivered at all of them; (2) replicas
  that delivered the same updates eventually reach equivalent state; (3) every method terminates.
- SEC = EC plus "correct replicas that have delivered the same updates have equivalent state".

**The six proof steps:**
1. **Delivery.** A path exists between every pair of nodes.
2. **Disjoint mailboxes.** No update arrives in two mailboxes of the same node, because a second path would
   contradict uniqueness of tree paths.
3. **Termination.** There are no loops, and nothing is sent back along its incoming path.
4. **Each mailbox variable holds exactly the updates delivered through it**, because max over an inflationary
   clock picks the latest cumulative value.
5. **No variable contains a duplicate.** None of the three writers can create one: local update, max-merge, or
   + over disjoint variables. Case 1 (local vs. mailbox) would need a loop. Case 2 (two mailboxes) would need two
   paths.
6. **`query() = +(local, neighbor₁.value, …, neighbor_k.value)`** is exactly the aggregate of every delivered
   update, each counted once.

### 4.4 Reconfiguration (§4.5) and faults (§4.6)

- **Initialization.** Either a balanced tree of configurable fan-out from an address list, or a minimum spanning
  tree from a distance matrix.
- **Join.** New nodes join as leaves: child C starts its clock at 0 and adds the parent's latest state, and the
  parent adds C.
- **Move one level** (Algorithm 2, verbatim). C moves from parent P to grandparent G:

```
At node C: atomic { ignore new messages from P; send state to G }
At node G: atomic {
  insert C ← (state_C.time, +(state_C.neighbors − state_C.P))
  merge P ← (state_C.P.time, state_C.P.val)
  send state to C, P (if alive) }
At node C: atomic {
  neighbors ← (neighbors \ {P}) ∪ {G}
  insert G ← (state_G.time, +(state_G \ {state_G.C})) }
At node P (if alive): atomic {
  neighbors ← neighbors \ {C}
  merge G ← (state_G.time, +(state_G \ {state_G.P})) }
```

  The essence: every update to a view of P is a `max_time` merge, so G's and C's views of P are fast-forwarded
  to the more recent one, and G "becomes the owner of the value of P".
- **Leave temporarily.** An internal node first "moves up" each of its children so that it becomes a leaf. Its
  parent keeps its clock and state.
- **Leave permanently.** The parent absorbs the departing node: `local ← local + state_C.local`, then forgets
  C's clock and entry.
- **Faults.**
  - *Process groups:* f+1 replicas per internal node. Synchronous replication keeps SEC; asynchronous
    replication gives only EC with possibly unbounded staleness.
  - *Reset:* drop all neighbor views, rebuild a spanning tree, and serve query results only after one full
    flooding round. That keeps query results moving forward.

### 4.5 Evaluation and limits (§4.7–4.8)

**Setup.** Implemented on DFIR in "< 400 lines" (§4.3.3) or "less than 300 lines" (§4.7); the chapter gives
both figures. Run on GCP n2-standard-4 machines, over TCP with `TCP_NODELAY` and bincode serialization, with
2¹⁴ counters.

**Results:**
- **Memory:** OnceTree stays constant at about 0.5 MB per node. PN-Counter and a mock "Delta-PN" grow linearly,
  reaching "10s or 100s of megabytes … at 2⁸ replicas".
- **Latency:** grows with log n for OnceTree, measured worst-case leaf to leaf. It is low at small n for the
  all-to-all baseline and then rises quickly.
- **Throughput:** OnceTree scales with the number of concurrent clients. PN-Counter saturates. Delta-PN matches
  OnceTree.

**Limits:**
- **Not causally consistent.** O(n) is a lower bound for causal consistency in the worst case (§4.8.1).
- Tree fragility.
- Latency is O(diameter).

### 4.6 What OnceTree means for us

OnceTree is the right transport when a **commutative monoid** aggregate (count, sum, sum of squares for variance,
or a Z-set of bounded support) is replicated to **many** nodes with **all-replicas-read** semantics:
metrics, like-counters, federated averaging, Tide global aggregates. It does *not* give free termination: see
§8.4 on PN-counters. We adopt it at **P2** (DIST-017, LIB-094). §4.8.2 claims OnceTree "can ensure that a
semiring-based language continues to behave correctly in a distributed environment". That is a direction, not a
construction, and we do not rely on it.

## 5. Supporting result: every undoable CRDT is a tuple of counters ([DOLAN])

**Model.** An op-based CRDT has states S and an initial state s₀, plus finitely many *partial* primitive
operations P.
- **Axiom 1 (commutativity):** if s·p and s·q are both defined, then s·p·q = s·q·p.
- **Axiom 2 (undoability):** if s·p is defined, some sequence q₁…qₙ returns to s.

**Results.**
- The actions applicable at s, taken up to equivalence, form a **finitely generated abelian group G_s**
  (Facts 1–6).
- By the fundamental theorem of finitely generated abelian groups, **every undoable CRDT is equivalent to a
  tuple of counters and modulo-n counters**.
- The PN-Set, a per-element counter, is undoable but reaches states where an element is present −1 times. The
  OR-Set has intuitive add and remove, but "doing and undoing a remove yields a different result from not
  removing at all".

**Consequence for us.** Z-sets, i.e. tuples of ℤ counters indexed by tuple, are the canonical undoable
replicated collection. There is no undoable set CRDT without −1 states. [WR] §5 and [FT] Thm 18 are the
engineering and termination faces of the same algebra. Our replicated collection library offers exactly three
deletion semantics (LIB-093, ODD-27):
- tombstone (2P);
- observed-remove (OR);
- Z-set with an optional client guard and clamping.

## 6. Deliverable 1: constructions for wrapping group- or ring-valued updates

### 6.0 Setting and notation

- G = (G, +, 0, −) is an abelian group. For Tide it is Z-set⟨T⟩, finite-support maps T → ℤ. For counters it is
  ℤᵏ.
- Updates g ∈ G originate at nodes (*origins*). Replica state is s = Σ(applied updates). Views are Q(s),
  maintained by DBSP Q^Δ (ENG-062).
- The network is DIST-001: messages may be dropped, duplicated, delayed and reordered. The requirement is that
  **every replica applies every update exactly once, in any order and any batching.** By commutativity and
  associativity it then converges to Σ(all updates). That is SEC for the state and, because Q is deterministic,
  for every view.

Inside our language, each wrapper is a **lattice relation** plus a **translation operator** `unwrap`. The
operator turns the lattice's per-tick Δ (ENG-043/044: keys whose value strictly grew) into a Z-set delta for
the DBSP stratum. That is the purple arrow in [WR] Fig. 1.

### 6.1 W1: unique-ID set ([WR] §3.1)

- **Lattice:** W1 = `Map<Uid, Point<G>>`.
  - `Point` is the equality lattice (LANG-124). Merging two different values for the same key is a hard
    `Conflict` error, because a UUID collision or a buggy re-send with a different payload must never be
    silent.
  - Merge is key-wise union.
- **Local update g:** choose a fresh `uid`, apply g to the group, and insert `uid ↦ g`.
- **unwrap:** Δ(W1) = the keys first seen this tick, and the output is Σ_{uid ∈ Δ} payload(uid).
- **Transport:** state-based. Gossip the whole map, or any subset of it. Loss, duplication and reordering are
  all harmless.
- **Cost:** metadata O(#updates ever) at every replica. Payloads are retained forever if gossip is state-based.
  [WR] gives no garbage-collection scheme.
- **Precondition:** + is associative and commutative. **Inverses are not needed.**
- **Use:** tests and small systems only. It is the reference oracle for W2 and W3.

### 6.2 W2: dots with cumulative acks and resend ([WR] §3.2, made precise [ours])

**Dot.** `Dot = (origin: NodeId, incarnation: u32, seq: u64)`.
- *incarnation* increments on every restart unless `seq` is durable. This is our addition: [WR] never
  discusses crashes, and reusing (origin, seq) after a crash makes the receiver **silently drop new updates**
  (BENCH-078).
- `seq` is assigned only to **non-zero** payloads. A skipped `seq` would leave a permanent gap in every
  receiver's context.

**Sender batching.** All updates a node makes to one wrapped channel within one tick are **summed** into a
single payload (associativity). If the sum is 0, nothing is sent and no seq is consumed. This is the group
analogue of DIST-005 "merge at the sender", and the zero case matches SEM-034 (⊥ ≡ nothing).

**Receiver state.** A causal context `CC: Map<(origin, incarnation), (contig: u64, exceptions: IntervalSet<u64>)>`.
This is a lattice under union of dot sets, in the style of a dotted version vector (LANG-134).

**Receive (d, g):**
- if d ∉ CC: CC ∪= {d} and G += g;
- otherwise do nothing.

The "changed" bit of the CC merge (ENG-044) is the gate. This is exactly the listing in §3.3, with compressed
IDs.

**Reliability.**
- The sender keeps `outbuf[d] = g` **durably**, in the same tick commit (DIST-020) as the local apply, until
  every current destination has acknowledged d. Without this, a crash after the local apply but before
  delivery leaves replicas diverged forever. This is our addition.
- An ack is the receiver's CC summary: per (origin, incarnation), `contig` plus the exception intervals. It is
  piggybacked or periodic, and it is cumulative, so lost acks are harmless.
- A timer resends every unacked dot to each destination. The "fixed interval" in [WR] is our timer relation
  (LANG-172).

**Membership.** A replica that joins receives either a snapshot of s plus the CC, or a replay of `outbuf`
covering its missing range. Acks are awaited only from destinations in the current membership epoch
(DIST-042). A departed replica's pending acks are dropped when the epoch is sealed.

**Correctness** [ours]:
- *Invariant:* s_r = base_r + Σ_{d∈CC_r} payload(d). Dots are globally unique by construction, so payload(d) is
  well defined.
- Every receive either adds a new dot and its payload, or changes nothing. The invariant therefore holds under
  any order, duplication or batching.
- Under fair delivery with resend-until-ack, every CC_r eventually contains every dot. So s_r converges to the
  same Σ at every replica.

**Cost:**
- receiver metadata: O(#(origin, incarnation) + #exception intervals). With resend this is the same order as
  the "number of replicas" claimed in [WR];
- sender metadata: O(unacked payloads);
- bandwidth: O(|g|) per destination, plus acks;
- latency: one hop.

**Relaying.** A relay may forward (d, g) unchanged, and dedup still holds.

**Retraction.** Negative weights inside g. The wrapper never inspects them.

### 6.3 W3: cumulative per origin ([DISS] §4.2.1 Node-ID-Map / PN-counter, generalized [ours])

- **Lattice:** W3 = `Map<(origin, incarnation), Lex<Seq, Point<G>>>`.
  - The value is the origin's **cumulative contribution** C_o(k) = Σ of its first k non-zero batches.
  - `Lex` is the lexicographic pair with a chain key (LANG-131): the higher seq wins, and an equal seq with a
    different value is a Conflict error.
- **Receive:** merge. **unwrap needs the old and the new value.** When origin o advances from (k, C) to (k′, C′),
  apply **C′ − C**. This is where the *group inverse* is used: the receiver turns a *state* message into a
  *delta*.
  - The merge primitive must therefore return `(old, new)` for each changed key. That is a small extension of
    ENG-044.
  - Without inverses (a plain commutative monoid), the replica instead recomputes s = Σ_o C_o. That is the
    Node-ID-Map trick exactly, at O(#origins) cost per read.
- **Transport:** anti-entropy of any subset of the map. It tolerates loss, duplication, reordering and
  **multi-hop gossip without acks**, because the latest cumulative value supersedes all earlier ones. An
  optional delta interval `(o, k→k′, C′−C)` may be applied only by a receiver currently at exactly k; any other
  receiver requests the full C_o(k′). This follows the pattern of R04 F51.
- **Cost:** O(Σ_o |support(C_o)|) at every replica. For counters and small-support Z-sets this equals a
  PN-counter. For large Z-sets it is prohibitive unless compacted.
- **Compaction** (P2, [ours]): once every replica in the epoch is known to hold C_o(k) (causal stability,
  LIB-087), fold C_o(k) into a shared `base` and re-express the entry relative to k.
- **Preconditions:** abelian group, for the difference form.
- **Use:** counter-like state over lossy gossip, and partition-healing anti-entropy.

### 6.4 W4: OnceTree ([DISS] ch. 4)

- **Per-node state:** `local: A`, and per tree neighbor `(clock, A)`, where A is any **commutative monoid**
  aggregate.
- **Message to neighbor i:** `(ts, local + Σ_{j≠i} state_j)`. **Merge:** keep the higher clock.
- **unwrap:** the node's group state is `local + Σ_j state_j`. The per-tick delta is `new − old` when A is a
  group. Otherwise the view is recomputed from the aggregate.
- **Preconditions:** A is associative and commutative; the overlay is a tree; there are no Byzantine nodes.
  Failures need the reset or process-group schemes (§4.4).
- **Cost:** O(degree × |A|) per node, and O(diameter) latency.
- **Guarantees:** SEC with **no causal consistency**. Queries are monotone in time *per node* only in the sense
  of "never goes backwards" in clock. With a group A the *value* can still fall, e.g. a count after a
  retraction.

### 6.5 How retraction is represented, end to end

| Layer | Representation | Rule |
|---|---|---|
| Update | Z-set weight −w | a delete is +(t, −1); a modify is −old + new ([WR] §2.2) |
| Network | inside the opaque payload of a dotted or cumulative wrapper entry | the wrapper never merges payloads with different dots; the sender may sum within one dot |
| Replica state | Z-set with weights in ℤ (checked i64 arithmetic; **overflow is a hard error**, never a wrap-around) | [ours] |
| Set view | `distinct`: {t : w(t) > 0} | DBSP incremental H (ENG-062) |
| Multiset view | w⁺ = max(w, 0) ("display all negative multiplicities as 0", [WR] §5) | declared per view |
| Client guard (optional) | a delete is dropped at the client when its observable count, i.e. the updates causally before it, is ≤ 0 | [WR] §5. The guard needs a read-your-writes session (LIB-085). Concurrent deletes can still reach −1. |

In Dedalus terms the per-tick **set** semantics of CR-03 is untouched. At the relation level, the wrapped
channel carries distinct `(dot, payload)` tuples. The Z-set lives behind `unwrap`, inside a declared weighted
collection (LANG-138).

### 6.6 The wrapper written in our language (illustrative; syntax per ODD-01 is still open)

The runtime operator ENG-070 is an optimized built-in, but W2 can also be expressed with existing features. We
keep this in the standard library as the executable spec (LIB-093):

```
// sender (every node is an origin)
durable table seqno(n: u64) key();                  // durable, so no incarnation bump is needed
scratch batch(item: T, w: i64);
batch(item, sum<w>) :- local_update(item, w);        // sender-side sum (associativity)
scratch nonzero() :- batch(_, w), w != 0;
seqno(n + 1) <+- seqno(n), nonzero();
durable table outbuf(seq: u64, item: T, w: i64);
outbuf(n + 1, item, w) <+ seqno(n), batch(item, w), w != 0;
gdelta(@R, self, s, item, w) <~ outbuf(s, item, w), replicas(R), R != self,
                                notin acked(R, self, s);          // resend until acked
// receiver
lattice seen: CausalContext;                          // LANG-134
seen <= dot_of(O, S) :- gdelta(_, O, S, _, _);
scratch fresh(O, S) :- seen.inserted(O, S);           // LANG-071 delta pseudo-relation = lattice Δ
zset counts(item) += w :- gdelta(_, O, S, item, w), fresh(O, S);  // unwrap into the Z-set (LANG-138)
ack(@O, self, seen.summary(O)) <~ ...                 // cumulative ack
```

`fresh` is exactly Δ(seen). Every dot is therefore added to `counts` once. The literal Dedalus resend semantics
(ODD-05) is *harmless* here, because duplicates are deduplicated. ARM suppression (ANA-061) is only a bandwidth
optimization.

## 7. Deliverable 2: what IVM can be replicated coordination-free, and how that changes the engine

### 7.1 The replication theorem, stated for our system

**Claim.** [WR] §3–4, with the proof shape of §6.2 [ours] and FT Cor 20. Let Q be any query that DBSP can
incrementalize (linear, bilinear, `distinct`, group-valued aggregation, stratified recursion) over input Z-sets
replicated by W1–W4. Then:
1. **Convergence (SEC):** replicas that have applied the same set of updates hold identical inputs and hence
   identical Q. Under fair delivery all replicas converge. **No coordination is needed.**
2. **No freshness or finality guarantee:** unless Q is constant, *no* replica state is an FT state for Q
   (Cor 20). A view value can always be changed by a future retraction. Q's outputs are **non-monotone over
   time**, so by CALM they cannot be emitted as never-retracted facts.

These are different properties, and both are true at once. *Keep CALM and CRDT On* (R05, R08 §8) separates
state convergence from query monotonicity in the same way. [FT] App. B formalizes it: the PN-Counter's state
semiautomaton is acyclic and inflationary, but "there is a fully invertible equivalent semiautomaton" with
respect to the query, so its value never freely terminates.

**Replicability by update algebra** (P = payload update type):

| P | Wrapper needed | Sender batching | Order needed | Can a threshold or view be final without a seal? |
|---|---|---|---|---|
| Semilattice (set, `lmax`, map-union, …) | none: raw lattice deltas, DIST-005/006 | merge | no | **yes** for thresholds over the lattice order (Prop 13) |
| Commutative monoid without inverses (ℕ-bags, sums of non-negatives, OnceTree aggregates) | W1, W2, W3 (recompute form) or W4 | sum | no | **yes** for thresholds that are monotone in the monoid's natural order (Prop 6, 13): e.g. `count(bag) ≥ k` once weights can only grow |
| Abelian group (Z-sets, PN, ℤₙ) | W1–W4 | sum | no | **never** for a non-constant query (Thm 18) |
| Ring (Z-sets with ⋈) | as for the group; × is local only ([WR] §4) | sum | no | never |
| Non-commutative (overwrite, sequence append, LWW without timestamps) | none is sufficient | none | **total order** (consensus) | per the finite-state analysis only |

The second row is a useful refinement. If ANA-030 proves a weighted stream is **insert-only** (all weights
≥ 0), the collection is an ℕ-bag. Its update is inflationary under pointwise ≤, so thresholds over it
terminate freely. A single retraction path, i.e. a possible negative weight, flips it to row 3. The distinction
between `bag` (ℕ) and `zset` (ℤ) should therefore be visible in types (LANG-138).

### 7.2 Changes to the hybrid engine (ODD-06)

1. **Boundary rule** [ours, from Strawman 2]. A Z-set diff may cross an async edge **only** through a wrapped
   channel (LANG-158, DIST-015..017). Lattice deltas keep the raw path of DIST-005/006. The compiler rejects a
   raw `<~` whose payload column is group-typed, unless the channel is declared exactly-once (ANA-015).
2. **The wrapper is a lattice stratum that feeds a Z-set stratum.** `unwrap` is linear in Δ(wrapper), so
   it composes with DBSP's `I` (integration) and with Q^Δ. The engine needs one new operator (ENG-070) and one
   small extension to ENG-044: merge returns `(old, new)` for W3.
3. **Edges from Z-set strata back into lattice or monotone strata are negative edges.** A view maintained with
   retractions can shrink. It is classified like a `<-`-maintained relation for stratification (SEM-021) and for
   the points-of-order report (ANA-022). The other direction is free: a monotone relation enters a Z-set stratum
   as an insert-only Z-set, since ℕ embeds in ℤ.
4. **Recursive views under deletion** (ENG-063) are unaffected: they run *inside* one replica.
5. **Fault tolerance.** W2's `outbuf` and CC are durable state (LANG-044). Replay after a crash deduplicates
   automatically, so recovery never double-applies. W3's map is its own checkpoint.
6. **LDFI.** "Payload of dot d applied at r" is a **monotone** goal: it is satisfied by *any one* delivery of d.
   Molly-2's hazard encoding (TEST-026) therefore treats resends as alternative supports. That is exactly why
   resend-until-ack protocols come out as robust.

### 7.3 Wire format (amends DIST-003/006; new DIST-015)

Every channel frame gets a **delta-kind tag**:

```
LDelta   { chan: u32, schema: u64, key: Tuple, delta: LatticeValue }          // idempotent: may be duplicated, pre-merged, relayed
GDelta   { chan: u32, schema: u64, dot: {origin: NodeId, inc: u32, seq: u64},
           payload: ZBatch }                                                   // W2: never merged across dots
GAck     { chan: u32, from: NodeId, cc: [(origin, inc, contig: u64, exceptions: [(lo,hi)])] }
GCum     { chan: u32, schema: u64, origin: NodeId, inc: u32, seq: u64, cumulative: ZBatch }   // W3 state
GCumDiff { chan: u32, schema: u64, origin: NodeId, inc: u32, from_seq: u64, to_seq: u64,
           diff: ZBatch }                                                      // W3 delta interval
OTAgg    { chan: u32, ts: u64, agg: AggValue }                                 // W4 OnceTree edge message
ZBatch   = n: varint, [(tuple: Tuple, weight: zigzag-varint i64)]              // canonical tuple order, no zero weights
```

**Receiver invariants:**
- A `GDelta` whose dot is already in CC is dropped and counted as a duplicate.
- A `GCum` or `GDelta` whose (key, seq) is already known with a *different* payload is a **hard error**
  (`Conflict`).
- A `GCumDiff` whose `from_seq` does not match is ignored, and the full `GCum` is requested.

## 8. *The Free Termination Property of Queries over Time* in full ([FT]; [DISS] ch. 3)

### 8.1 Model (§3)

- **Def 1 (semiautomaton).** S = (D, L, U) with U : D × L → D *total*. When D is finite this is a DFA with no
  initial or accept states.
- **Reachability.** s ↠ s′ means s′ is reachable by a finite sequence of steps. U^k(s) is the set of states
  reachable in at most k steps, and U^∞(s) = ⋃ₖ U^k(s).
- **Def 2 (transition graph).** G[S] has vertex set D and edges {(s, s′) : ℓ | s′ = U(s, ℓ)}.
- A **query** is a total function Q : D → R.
- **Def 3 (free termination state).** s is an FT state iff **∀ s′ ∈ U^∞(s): Q(s) = Q(s′)**. "The distributed
  system can output the value of Q without the need to continue the computation."
- **Ex 4 (Fig. 1).** Four DFA shapes over {a, b, c}:
  - (a) "contains an a": an FT state is reachable from everywhere, and all FT states agree;
  - (b) all paths reach FT states, but different FT states give different values;
  - (c) "odd number of b's": no FT states;
  - (d) some paths reach FT states and others do not.
  The dissertation's Fig. 3.1 marks the FT states with ★.

**Instantiations (§3.1):**
- **S∪.** D is all instances of a schema, L is all tuples, and U(I, t) = I ∪ {t}. For a Boolean conjunctive
  query, I is FT iff Q(I) = T. If Q(I) = F, "we can always insert a sequence of tuples to make Q true."
- **State-based CRDT S□.** U(s, ⟨u, ℓ⟩) = update(s, ℓ) and U(s, ⟨m, s′⟩) = merge(s, s′). Its transition system
  "will always be acyclic".
- **Fixpoint computation.** Naive or semi-naive Datalog evaluation is parameter-independent. The fixpoint is
  trivially FT, but a query may be FT **earlier**. Verbatim:

```
P(x,y) ← Edge(x,y)
P(x,y) ← P(x,z), Edge(z,y)
Q() ← P(s,t)
```

  "We can freely terminate as long as the state contains the IDB fact P(s,t), even before we have reached a
  fixpoint." The same holds for `Q′() ← P(x,x)`, cycle detection. For Datalog° over POPS, the following
  "min-plus distance ≤ 10" query has FT states:

```
P(x,y) ← min(Edge(x,y), min{(P(x,z) + Edge(z,y))})
Q() ← P(s,t) ≤ 10
```

### 8.2 Partial orders and thresholds (§4.1)

- **Def 5 (inflationary / deflationary):** s → s′ ⇒ s ⊑ s′ (respectively s ⊒ s′).
- **Prop 6:** if U is acyclic ignoring self-loops, then s ⊑_U s′ ⇔ s ↠ s′ is a partial order (the **natural
  order**), and S is inflationary with respect to it. For a monoid update, x ⊑ y iff ∃z: x →ᶻ y. **Ex 7:** the
  natural order of S∪ is ⊆.
- **Def 8 (monotone / antitone query):** s ⊑ s′ ⇒ Q(s) ⊑ Q(s′) (respectively ⊒).
- **Prop 9:** with inflationary S and a *maximal* s (or deflationary S and a minimal s), s is FT. In particular
  **⊤ is always FT**.
- **Prop 10:** with inflationary S, monotone Q and Q(s) maximal in R, s is FT. With antitone Q and Q(s)
  *minimal*, s is FT.
- **Ex 11:** "every element is an a" is antitone. It is FT once it is F.
- **Def 12 (Boolean threshold query):** for an antichain C (the *threshold line*), Q_C(s) = ⋁_{c∈C} (s ⊒ c).
- **Prop 13:** with inflationary S, **the FT states of Q_C are exactly the states at or above C.** The remark
  after it: *"any monotone Boolean query must be a Boolean threshold query (excluding the trivial query that is
  always false)."*
- **Prop 14 (acyclic U):** if Q has at least one FT state, there is an antichain C, namely the minimal FT states,
  such that c ⊑_U s ⇒ Q(s) = Q(c). This is a *generalized threshold* whose elements may have different values.
- **Prop 15 (natural order is a join-semilattice):** **all FT states return the same value**. The corollary:
  "any free termination state in a state-based CRDT must have the same value", namely Q(⊤) when ⊤ exists.
- **Prop 16 (same setting):** if any FT state exists, **every state can reach one**.
- **Queries that are neither monotone nor antitone can still have FT states.** Example: Q() = R(c) ∧ ¬S(c) is
  FT exactly in the states that contain S(c).

### 8.3 Commutativity (App. A; DISS §3.4.2)

- **Def 32:** U is commutative if s·a·b = s·b·a for all label sequences. Q is commutative if
  Q(s·a·b) = Q(s·b·a). A commutative U implies a commutative Q, but not conversely: counting the a's under
  string concatenation is a commutative query over a non-commutative update.
- Set insert/delete is **not** commutative. Z-set insert/delete **is**, and forms an abelian group.
- **Prop 33:** with a bottom state ⊥ and a commutative Q, all FT states agree.
- **Prop 34:** with ⊥ and a commutative U, if Q has any FT state, every state can reach one.

### 8.4 Group-like structures: the inverse curse (§4.2)

- **Def 17:** an *identity state* id reaches every state. A state is *invertible* if it can reach an identity
  state.
- **Thm 18 ("the inverse curse theorem"):** if every state is invertible, **a non-constant Q has no FT states**.
  Proof: s ↠ id ↠ s′ with Q(s′) ≠ Q(s).
- **Ex 19:** a counter on ℤ with ±1 has no FT states for any non-constant Q.
- **Cor 20:** if (D, U) is a group, a non-constant Q has no FT states. So "in view maintenance, which often
  studies rings rather than semirings, **free termination is impossible**". The paper calls this a dichotomy:
  the benefits of invertibility (DBSP, DBToaster) and of coordination-free monotone queries (CALM, CRDTs) "appear
  mutually exclusive".
- **App. B** on the four CRDTs:
  - *G-Set:* every threshold result applies.
  - *2P-Set:* "we can **negatively** partially freely terminate on any value in DELETES" but "never positively".
    Its query-equivalent graph has cycles but is "not fully invertible".
  - *G-Counter:* max merge; thresholds on Σ are FT.
  - *PN-Counter:* "all integer query results are reachable from all states", so there is no FT for a
    non-constant query on the value, even though the internal state is an inflationary lattice.

### 8.5 Distributed model (§5)

**Network model.** A finite connected undirected graph. The instance I is horizontally partitioned. Each node is
an S∪ semiautomaton (oblivious, *network flooding*). A configuration is (state, buf, ready), with three
transition kinds:
- **Produce:** move a local tuple to a neighbor's buffer.
- **Consume:** move a buffered tuple into local state.
- **Ready:** set ready(v) ← T, which is irrevocable.

A run is **fair** if every buffered fact is eventually consumed, and **complete** if every local tuple is
eventually sent. The algorithm is **correct** if whenever ready(v) = T, Q(state(v)) = Q(I). Every run reaches a
quiescence point, but "without coordination, it is not possible to know when a node has received the entire
input."

**Results:**
- **Def 21 (coordination-free correct):** some algorithm, on every fair and complete run, computes the correct
  output and sets ready everywhere.
- **Thm 22:** (Q, I) is coordination-free correct **iff I is an FT state for Q in S∪**. The algorithm: "set
  ready(v) to true exactly when state(v) is a free termination state."
- Coordination-freeness is therefore a property **of a (query, input) pair**. Requiring it for every input
  leaves only the constant queries.
- **Def 23:** Q is *positively* (respectively *negatively*) coordination-free if (Q, I) is coordination-free
  correct for every I with Q(I) = T (respectively F). **Positive coordination-freeness is exactly the transducer
  notion of CALM** ([Ameloot et al.]).
- **Thm 24 (Boolean):** positively CF ⇔ **monotone**; negatively CF ⇔ **antitone**. An example of the latter
  is ∀x: R(x) > 0. Ameloot et al. call antitone queries non-computable by oblivious transducers only because
  their outputs encode "false" as absence.
- **Non-Boolean queries:** there is one ready bit per (node, tuple). **Thm 25:** Q is positively (respectively
  negatively) CF ⇔ monotone (respectively antitone). Worked example: Q(x) = (R(x) ∧ x > 10) ∨ (S(x) ∧ ¬T(x)).
  R(20) makes (20) final-true, and T(5) makes (5) final-false.
- **§5.2 metadata.** The `All()` relation of Ameloot et al.: every outgoing transition from a state with
  All = T is a self-loop, so **every state with All = T is FT**. "The tradeoff is that updating All requires
  coordination."
- **App. C, policy-aware transducers.** State is (I⁺, I⁻) with I⁺ ∩ I⁻ = ∅. A node may add t to a neighbor's
  I⁻ when the distribution policy says the neighbor cannot hold t. Ī is the set of adom-tuples not in I.
  - **Thm 35:** (Q, I) is CF correct iff (I, Ī) is FT in S±∪.
  - **Thm 36:** positively CF ⇔ *domain-distinct-monotone*, where Q(I) ⊆ Q(I ∪ J) whenever every fact of J has a
    constant outside adom(I). The printed "resp." clause says "domain-distinct-monotone" twice, in both arXiv
    and LIPIcs. It should read domain-distinct-**antitone**, since the proof ends "The antitone case is
    symmetric".

### 8.6 Finite state: decision procedure and minimization (§6)

**Prop 26 (linear time; the algorithm verbatim in steps):**
1. If s is FT, every state in s's SCC is FT. So an SCC with two different Q values contains no FT state.
2. Condense G[S] into its SCC DAG G′.
3. Mark an SCC as a *candidate* if Q is constant on it. Otherwise remove it, *and every node that can reach
   it*, from G′.
4. Traverse the remaining DAG G″ in **reverse topological order**:
   - an SCC with no outgoing edge in G″ is FT;
   - an SCC whose outgoing edges all lead to FT SCCs with the *same* Q value is FT;
   - otherwise it is not FT.

The total is O(|G[S]|), assuming Q costs O(1). "It is desirable to determine whether the current state is a
free termination state" at runtime. Checking a single state is a linear reachability check.

**Cor 27:** the FT states of a DFA can be computed in time linear in the DFA's size.

**Def 28 (equivalence of (S,Q) and (S′,Q′)):** identical query results for identical label sequences from ⊥.

**Prop 29:** in a minimal DFA, no FT state lies on a cycle.

**Prop 30:** collapsing U^∞(s) of an FT state s into a single self-looping state s₀ preserves equivalence.
Repeating this until nothing changes, which needs a finite state space, gives the *collapsed* pair (S□, Q□).

**Prop 31:** in (S□, Q□), s is FT **iff all its outgoing transitions are self-loops**.

**Remark (§6.2).** "While CRDTs appear to only describe inflationary state mutations, it is common to convert
non-inflationary updates into inflationary ones using metadata." The 2P-Set and the PN-Counter are acyclic, but
their query-equivalent representations are cyclic.

### 8.7 The "Generalized CALM Agenda" ([DISS] §2.3)

Power proposes separating "CALM Theorem" (the proven transducer result) from a broader agenda. The agenda:
- generalizes monotone to **inflationary**;
- drops the restriction to Datalog;
- studies what monotonicity buys: fixpoint convergence, semi-naive evaluation, incrementality, partitioning,
  pipelining, SIP, partial progress on partial inputs, disorderly evaluation, invariants on outputs over time,
  and replica convergence.

Free termination addresses "invariants on global outputs over time". This matches the scope of our ANA section.

## 9. Deliverable 3: free-termination criteria as analyses we can implement

### 9.1 The object we analyze

For node n and output O, the relevant semiautomaton has:
- **D:** node n's reachable states (all relations, lattices and Z-sets, modulo time; ENG-120);
- **L:** the per-tick input batches of SEM-080: deliveries, timer events, host inputs, and `now`/`random`
  samples;
- **U:** one tick transition (SEM-002).

**SEM-016** defines finality from this: *a fact (or value) of O at node n, tick t, is **final** iff n's state
at t is an FT state for the query "is this fact in O" (or "the value of O"), relative to every fair
continuation that respects the declared seals, schemas and fault model.* Two properties follow directly from
Def 3:
- **Finality is monotone in time.** U^∞(s′) ⊆ U^∞(s) whenever s ↠ s′, so an FT state reaches only FT states
  with the same value. **Finality bits can be emitted as never-retracted facts**, i.e. G-Set lattice facts, and
  shipped over raw lattice channels.
- **Cross-replica agreement is a separate question.** Prop 15 and Prop 33 guarantee agreement only if the
  node's update structure is a join-semilattice or commutative. Otherwise, as in Fig. 1b, two nodes can reach
  different FT states. "Final and consistent" = finality (ANA-120/091) **and** a confluence certificate
  (ANA-029).

**Quiescence ≠ termination.** SEM-010 quiescence ("state equivalent modulo time to t−1 and no pending inputs")
is visible only to a *global observer*: the simulator or the model checker. A node cannot detect quiescence
locally, because a grow-only set "do[es] not support free termination" ([FT] §1.1). SEM-010 must be labeled
simulator-only. Runtime termination and finality use SEM-016.

### 9.2 Is there a decidable static check?

**No, in general** [ours; this does not appear in the papers]. We show that deciding whether the empty state is
FT for a first-order Boolean query over S∪ is undecidable:
- Take any FO sentence φ, and let P be a fresh nullary predicate.
- Let Q = φ ∧ P(). Then Q(∅) = F.
- ∅ is FT ⇔ no finite J satisfies φ ∧ P() ⇔ φ is finitely unsatisfiable. This is undecidable by Trakhtenbrot's
  theorem.
- The same construction shows that **monotonicity of FO queries is undecidable**: Q is monotone iff φ is
  finitely unsatisfiable, because a model I of φ gives Q(I ∪ {P}) = T but Q(I) = F with I ⊆ I ∪ {P}.

Non-recursive stratified Datalog¬ captures FO, so the deductive reduction of our programs inherits this.

**What is decidable, and what we implement:**
- **Positive (negation-free) programs over inflationary state.** Every output tuple is final the moment it is
  derived (Thm 25, positive). A Boolean output is FT iff it is true, unless Q is unsatisfiable (Thm 22 + Prop 13).
  This is decidable, trivially.
- **Declared finite-state components.** Exact FT by Prop 26 (ANA-122).
- **Syntactic classes** (ANA-120). These are sound and incomplete. The classes are listed below.
- **A runtime bound test** (ANA-121). Sound, incomplete, and polynomial per tuple.

### 9.3 ANA-120: static finality classes (sound, incomplete)

Every output relation (or per output column pattern) gets one or more of the following. The tool reports each
with its evidence.

| Class | Criterion (ours, derived from the cited result) | Source result | Emission rule |
|---|---|---|---|
| **POS-FINAL** | Every path from inputs to O is monotone (ANA-020), all base inputs are inflationary, and O is a set or threshold output | Thm 24/25 (positive); Prop 13 | a tuple, or `true`, is final when derived |
| **NEG-FINAL** | O is antitone in its inputs: an odd number of − edges (ANA-021), e.g. ∀, `notin` over an inflationary relation, `lmin` reaching the output's minimum | Prop 10 (antitone); Thm 24 (negative); Ex 11 | absence, or `false`, is final when refuted |
| **TOP-FINAL** | A lattice-valued output reaches a maximal element of its type: `lbool` true, `WithTop` ⊤, a bounded `lmax` at the domain max, `Conflict` ⊤ | Prop 9, Prop 10 | the value is final at ⊤ |
| **THRESH-FINAL(C)** | A generalized threshold `threshold(t₁..tₙ)` over inflationary state with **pairwise incompatible** tᵢ (LANG-126) | Prop 14 + Prop 15 [our connection, below] | the value is final at the first tᵢ crossed |
| **MIXED** | Anything else built from +/− paths over inflationary or sealed relations | Thm 25 per tuple; §4.1 example R(c) ∧ ¬S(c) | per-tuple runtime test (ANA-121) |
| **FINITE** | The output depends only on a declared finite-state component | Prop 26, Cor 27, Prop 31 | table lookup (ANA-122) |
| **SEALED(S)** | Finality needs seals S (ANA-065, LANG-207) | §5.2 `All()` | final once the seals arrive; the seal costs coordination (ANA-046) |
| **NEVER-FINAL** | O depends non-constantly on a relation whose update semiautomaton is invertible (next table) and no seal closes it | **Thm 18, Cor 20** | only provisional values; a `final` annotation is a compile error |

**Why pairwise incompatibility is required for multi-valued thresholds** [our connection]. Prop 14 needs only an
antichain. But if two threshold elements c₁ and c₂ with Q(c₁) ≠ Q(c₂) have a *reachable* common upper bound s,
then Q(c₁) = Q(s) = Q(c₂), a contradiction. In a join-semilattice every pair has one (Prop 15). So distinct
values are only possible when the tᵢ are **incompatible**, meaning their join is ⊤ or unreachable. This is
exactly the LVars/Flo requirement already in LANG-126. The two lines of work agree.

**Detecting invertibility for NEVER-FINAL**, conservatively [ours]. A relation R is *invertible-driven* if any of
these holds:
- its writers include a **Z-set input or channel** that can carry negative weights (ANA-030 cannot prove it
  insert-only);
- a **host input with deletions**;
- `<-` or `<+-` driven by an unsealed external input;
- R is a **PN-style value** (P − N).

Set insert/delete from arbitrary external sources already makes every state invertible, since ∅ is an identity
state. **Thresholds over the internal lattice of a PN-counter are not thresholds over its value.** `pn.value ≥ 10`
is NM (never final), while `pn.pos ≥ 10` is monotone and POS-FINAL. LANG-125's classification must list
`value` as NM, per [FT] App. B.

### 9.4 ANA-121: the runtime bound ("Kleene") finality test [ours; sound by construction]

**Relation classes:**
- **INFL(R):** content only grows. This covers `table` with no `<-` or `<+-`, lattices (SEM-030), `range`,
  `sealed`, and IDB derived from INFL relations by monotone rules.
- **CLOSED(R)** or **CLOSED(R, k):** a seal (LANG-207), `static`, or a `sealed` collection after bootstrap. No
  future change is possible for R, or for R's partition k.
- **OPEN:** everything else.

**Base bounds for every future state J reachable under fair runs:**
- Lower bound L(R): R now if INFL(R) or CLOSED(R), otherwise ∅.
- Upper bound Up(R): R now if CLOSED(R), otherwise ⊤ (symbolic "open").
- Then L(R) ⊆ J_R ⊆ Up(R).

**Two derived models:**
- **M⁻ (certain):** evaluate the stratified program with positive atoms over L, and satisfy `notin A` only if
  A ∉ M⁺, i.e. certain absence.
- **M⁺ (possible):** evaluate with positive atoms over Up, and satisfy `notin A` if A ∉ M⁻, i.e. possible
  absence. M⁺ is computed **demand-driven** for the requested output tuples (magic sets, ENG-092). An open
  positive atom counts as "possibly true" for any binding.

By induction over strata, with negation swapping the bounds, **M⁻(O) ⊆ O(J) ⊆ M⁺(O) for every reachable J.**
So:
- t is **final-present** iff t ∈ M⁻(O);
- t is **final-absent** iff t ∉ M⁺(O).

**Aggregates** use interval bounds:
- count and sum over non-negative contributions: [agg(M⁻), agg(M⁺)], with ∞ when open;
- `min`: [−∞ if open else min(M⁺), min(M⁻)];
- a threshold `agg ≥ k` is final-true when the lower bound is ≥ k, and final-false when the upper bound is < k.

**Lattice outputs:** final when the lower value is maximal in the output type (Prop 9/10), or when
lower = upper (closed).

**Coverage:**
- R(c) ∧ ¬S(c) with S(c) present and S inflationary is final-false.
- The §5.1 mixed query decides (20) true and (5) false.
- |R| > 10 is final-true at 11 tuples, and final-false only once R is sealed.
- ∀x R(x) > 0 is final-false on the first violating fact.
- The PN value interval stays (−∞, ∞) while either side is open.

**Incrementality.** M⁻ only grows and M⁺ only shrinks as time advances and seals arrive. So finality is
maintained semi-naively: M⁻ with lattice-style Δs, M⁺ with the retraction machinery (ENG-062) on a small demand
set. This is ENG-071.

**Early exit inside a fixpoint** (the §3.1 "Fixpoint Computation" observation). If the only consumer of a
recursive stratum is a POS-FINAL Boolean goal, evaluation may stop as soon as the goal is in M⁻. This generalizes
ENG-048 early exit for nullary heads.

### 9.5 ANA-122: exact FT for finite-state components (Prop 26)

1. The programmer marks a component `finite` (for example, the per-key state machine of a 2PC transaction:
   {init, prepared, committed, aborted}). Otherwise, the analysis infers one when every relation involved has a
   finite-domain type and a bounded per-key cardinality. The analysis enumerates the abstract states per key, up
   to a configurable cap such as 10⁵, beyond which it is a hard error.
2. It builds the per-key transition graph. The edges come from the inductive rules under **every** input label
   the channel schemas allow. Over-approximating edges only removes FT states, so this is sound.
3. It runs the Prop 26 algorithm. It emits a static table `ft_state(state) → value` and, via Prop 30/31, a
   collapsed automaton. The runtime check is O(1): "is this state's collapsed node self-looping?"
4. **Homomorphic abstraction** [ours]. For infinite D, suppose h : D → D′ is a congruence
   (h(U(s,ℓ)) = U′(h(s),ℓ)) and Q = Q′∘h. Then h(s) FT in S′ ⇒ s FT in S. Example: [FT] §1.1's "is the running
   product even?" maps to ℤ/2 = {even, odd}, and `even` is absorbing.
5. **Uses:**
   - 2PC and Paxos decisions: `committed` and `chosen` are absorbing, so they are final, which serves both GC and
     final outputs;
   - Raft `commitIndex`, which is a monotone max: TOP-FINAL per index;
   - timer and phase automata;
   - DFA-encoded temporal specs.

### 9.6 When a node or job may declare output final or terminate

| Situation | May declare final? | Source |
|---|---|---|
| Monotone threshold or tuple over inflationary inputs, and it holds | **yes, unilaterally** | Prop 13; Thm 24/25 |
| Monotone threshold that does not hold yet | **no**, possibly never ("only offer free termination for database instances where the answer is true!") | §1.1 |
| Antitone query refuted by present evidence | **yes, unilaterally** (as false or absent) | Prop 10; Thm 24 |
| Non-monotone query whose bounds decide it (M⁻ / M⁺) | **yes, per input** | Thm 22; ANA-121 |
| Output over invertible state (Z-set views, PN value, deletable host input) | **never without a seal** | Thm 18; Cor 20 |
| After a seal or `All()` on every relation the output depends on | **yes**; the cost is the coordination that produced the seal | §5.2; ANA-046 |
| Finite-state component in an FT state | **yes** | Prop 26 |
| Node termination (`halt`, LANG-052) | allowed iff **every** output the node serves is final and no obligation remains to relay for others (resend buffers, OnceTree edges) [ours] | Def 3 applied to the whole output set |

**Relation to CALM, seals and thresholds:**
- CALM's coordination-freeness is POS-FINAL: positive CF ⇔ monotone (Thm 24/25).
- Free termination adds NEG-FINAL, per-input finality for non-monotone queries, and TOP-FINAL.
- Thresholds are exactly the monotone Boolean queries (the remark after Prop 13).
- Seals are the metadata that make states FT (§5.2). So coordination is exactly *how we buy finality* for
  inputs that are not FT.

**Batch and streaming job completion** (FLAG-122/129, new FLAG-141):
- **Batch stage.** A bounded input source emits a whole-relation seal after its last split. Downstream outputs
  become final by SEALED propagation, and threshold outputs may finish earlier. A job terminates when every
  output relation is final. The job master can check this locally by its own ANA-121 bounds, with no extra
  coordination round beyond the seals.
- **Streaming panes.**
  - The watermark is a `lmax` threshold, i.e. a seal on event time below the watermark.
  - An accumulating pane over an insert-only stream is POS-FINAL for thresholds, and SEALED at the watermark
    for its value.
  - An **accumulating-and-retracting** pane is Z-set valued: NEVER-FINAL until the watermark seal. It must be
    labeled *provisional* until then.
  - Data that arrives late for a sealed window is a declared policy: drop it, or emit to a separate
    corrections stream that is never final. It is never a silent update of a pane already emitted as final
    (TEST-088 checks this).

## 10. Emmy and the state of Hydro's property checking

**Emmy ([DISS] ch. 6).**
- **Goals:** "Developers don't have to read or write verification code", and "0% false positives on determining
  that an algebraic property is satisfied".
- **Tools:** Kani (bounded model checking directly on Rust) for bounded types; `cargo fuzz` for unbounded types.
  Fuzzing can only *refute*, so a fuzz-only property is surfaced as advice and never trusted.
- **Scope:** properties are hard-coded as assertions. Kani supports associativity, commutativity and
  idempotence; the fuzzer supports every property in §2.1. About 2000 lines of Rust.
- **Dataset:** GitHub closures passed to `.fold()` (about 131k) and `.reduce()` (about 22k), filtered to
  self-contained closures over bounded types and syntactically deduplicated. That leaves 4,913 fold closures
  and 1,058 reduce closures, which are 61 semantically unique.
- **Kani proof rates:** fold 86% / 86% / 99% (assoc / comm / idem); reduce 83% / 83% / 99%.
- **Failures:** Kani times out on multiplication (a known BMC weakness) and on the loop-based LCM closure
  (Fig. 6.5).
- **Assoc, comm and not idem, as proved by Kani:** + and XOR. These are exactly the candidates for OnceTree.

**Hydro today** (`9e2a120`, PR #3198 merged 2026-09-17):
- *Retries markers.* `ExactlyOnce` and `AtLeastOnce` are marker types on streams. `ValidIdempotenceFor<ExactlyOnce>`
  is implemented for `NotProved`, but `ValidIdempotenceFor<AtLeastOnce>` only for `Proved`. The error text is
  "Because the input stream has retries `{R}`, the closure must demonstrate idempotence with an
  `idempotent = ...` annotation."
- *Commutativity* has the same structure over `TotalOrder` and `NoOrder`.
- *Upgrading retries.* `unique()` returns an `ExactlyOnce` stream. `unique` on `(dot, payload)` is therefore
  precisely W1/W2 dedup, expressed as a type upgrade.
- *Proof mechanisms.* Proofs are either `manual_proof!(/** reason */)` or, since #3198, the Verus-checked
  `verus_proof_commutative_{fold,map,filter,effect}!`.
- *What #3198 says.* Obligations are generated from the *actual closure body*, shape-specific, and quantified
  over declared captures. It found "a genuine soundness bug": a `map` emitting a running total under a
  `manual_proof!`. The simulator "does not trust commutativity proofs"; it still explores orderings.
- *Status of Emmy integration.* Issue #1877 ("Integrate Emmy to formally verify algebraic properties of quoted
  closures") was closed by #3198, which uses Verus rather than Kani.

**For us.** Rules are analyzable, so most algebra is *syntactic*: `+` on a Z-set is a group, `max` is a
semilattice. Proof obligations arise only for **UDFs and user-defined aggregates or lattices** (LANG-105,
LANG-135, LANG-182). TEST-087 adopts Emmy's policy:
- *proved* means BMC or SMT succeeded, and it enables optimizations and the ANA-015 upgrade;
- *tested* means fuzzing passed. It gives a warning only, and needs `nondet` to be relied on;
- *refuted* means a counterexample was found, and it is an error.

  logical task, with no incarnation, because deterministic re-execution regenerates identical batches (R14
  ANA-037). DIST-015 is the general form, for arbitrary group payloads and arbitrary producers, including
  nondeterministic producers. For those, the incarnation rule of §6.2 is mandatory. The deterministic-producer
  case may reuse ids, and that is exactly the attempt-agnostic dedup R14 certifies.
- **LANG-112 (R14)** already says "Non-idempotent partials must travel with exactly-once identities (DIST-011)".
  CR-35 is the general rule behind it: an idempotent group is trivial.
- **ANA-036 (R14: early-emission classes T/L/A/H/W)** is a *reducer-level* instance of ANA-120:
  - T ⊆ POS-FINAL/THRESH-FINAL;
  - L is "progressive, not final": a lower bound in a lattice order that is POS-FINAL only for thresholds over
    it;
  - A and H are estimates, never final;
  - W = SEALED(window).

  ANA-120 adds NEG-FINAL, TOP-FINAL, MIXED, FINITE and the NEVER-FINAL inverse-curse class, which R14's classes
  do not cover.
- **FLAG-138 (R14: bound-based early finalization, `[lo, hi]` per key)** is the interval-aggregate part of
  ANA-121, specialized to rank outputs. ANA-121 supplies the soundness argument (M⁻ ⊆ O(J) ⊆ M⁺) and extends it
  to negation and recursion.
- **CR-33 (R14: "Are snapshots monotonic?")** is consistent with FT Prop 10 and Cor 20. A class-A snapshot over
  retractable input is NEVER-FINAL. Only the sealed final snapshot is deterministic.

## 12. TEST PROGRAMS (end-to-end, with expected behavior)

Syntax is illustrative (ODD-01). "Chaos" means the simulator (TEST-001) duplicates every message 1–4× at random,
reorders arbitrarily, and drops 30% of first transmissions. Resends are driven by a 3-tick timer. All runs use
the TEST-002 exploration modes. Every test is also checked against W1, the unique-ID oracle.

**T1: replicated count with retractions over a duplicating channel (BENCH-073, P0).**
- **Setup:** replicas A, B, C. Local Z-set `counts(item)`. Channel `vote_d` is wrapped with W2 (dots).
- **Host operations:**
  - A: +x at tick 1; +x at tick 2.
  - B: −x at tick 1. B has not yet seen A's updates, and there is no client guard in this variant.
  - C: +y at tick 1.
  - A: −y at tick 5, after observing C's +y.
  - B: +z and −z at tick 3, in the **same tick**. They sum to 0: no dot is assigned and nothing is sent.
- **Expected:**
  - Every replica eventually has x = 1, y absent (weight 0), and z never present.
  - Multiset view {x: 1}; set view {x}.
  - Between ticks 1 and ~3, B's raw weight for x may be −1. Its clamped view shows 0.
  - The instrumented number of payload applications equals the number of distinct dots: 5 dots (A1, A2, A3,
    B1, C1) applied at each remote replica. Duplicates are counted as dropped.
  - `output final count_view` is **rejected** by ANA-120: NEVER-FINAL (Thm 18).
- **Negative variant:**
  - Declaring `vote_d` as a plain channel with a raw weight column is a compile error (ANA-015).
  - Forcing it with `nondet "..."` lets the simulator find a schedule with x ≠ 1. Duplicating A's first +x
    gives x = 2 at C.

**T2: cumulative wrapper over lossy gossip with a line topology (BENCH-074, P1).**
- **Setup:** the operations of T1 on a line A — B — C, with no A–C link. W3 anti-entropy every 5 ticks sends
  each node's full `Map<origin, Lex<seq, cumulative>>`. There are no acks, 50% loss and chaos duplication.
- **Expected:**
  - The same final state as T1.
  - C learns A's contributions through B's relayed entries.
  - Applying (k → k′) to the group equals C′ − C, so no double counting occurs even when an older cumulative
    arrives after a newer one; it is ignored by Lex max.
- **Mutation test:** replacing the "apply C′ − C" with "apply C′" must make the fuzzer find divergence.

**T3: concurrent deletes (BENCH-076a, P1).**
- **Setup:** x has count 1 at both A and B, from an earlier +x at C. Clients at A and B each delete x once,
  concurrently, with guards on. Both guards see count 1, so both deletes are allowed.
- **Expected:** final weight −1 everywhere; clamped multiset view 0; set view has no x. This is documented
  behavior per [WR] §5. It is *not* a bug, and the test pins it.

**T4: guarded delete-then-insert (BENCH-076b, P1).**
- **Setup:** at A, a client deletes w when its observable count of w is 0, then inserts w.
- **Expected:**
  - With the guard, the delete is dropped at the client, and the final weight is w = 1.
  - Without the guard, the final weight is w = 0 (the insert/delete anomaly of [WR] §5).
- **Also:**
  - The 2P-Set variant: w is never re-insertable, and `w ∈ DELETES` makes "w absent" NEG-FINAL.
  - The OR-Set variant: Dolan Fig. 1a/1b. Remove-then-re-add ends with w present. Doing and undoing a remove
    ends with w present in Fig. 1a, but w absent when no remove happened (Fig. 1b). The test pins both.
  - The PN-Set variant: the add, remove, remove sequence reaches the −1 state, and it takes a later add to reach
    empty.

**T5: a monotone query that is freely terminating and one that is not (BENCH-097a, P0).**
- **Program:**
  ```
  P(x,y) :- Edge(x,y).   P(x,y) :- P(x,z), Edge(z,y).   reach() :- P(s,t).
  ```
  Edges arrive over a channel. Edge is a persisted table, so it is inflationary.
- **Instance 1:** the edges s→a, a→t arrive at ticks 1 and 3; further edges keep arriving until tick 50.
  - `reach()` is **final-true at tick 3**, the moment P(s,t) is derived (Prop 13).
  - It is also final *before* the local fixpoint when the fixpoint is still running. The early-exit counter shows
    fewer rule firings than the full fixpoint (ENG-071).
- **Instance 2:** edges arrive but none connects s to t.
  - `reach()` stays **provisional forever**. The query is monotone, but no reachable state is FT for the instance
    (§1.1: thresholds are FT "only … where the answer is true").
  - After `seal Edge`, `reach()` becomes final-false (SEALED).
- **Cardinality variant:** `big() :- count<*> Edge > 10` with only 7 edges ever sent. It is monotone and never
  final until the seal, after which it is final-false.
- **Per-tuple versus whole-answer:** each derived `P(x,y)` tuple is final-present on derivation (Thm 25). The
  *set* P, and any query equating it to a value such as `count P = 12`, is never final before the seal.

**T6: non-monotone queries that terminate freely on some inputs (BENCH-097b, P0).**
- `q() :- R(c), notin S(c)` with R and S persisted: q is provisional-true after R(c), and **final-false** once
  S(c) arrives.
- `q(x) :- R(x), x > 10.` and `q(x) :- S(x), notin T(x).` (the §5.1 query):
  - with inputs R(20), S(5), T(5): (20) is final-present, and (5) is final-absent, because both disjuncts are
    refuted: 5 > 10 is false and T(5) is present;
  - with input S(7) only: (7) is provisional-present.

**T7: antitone query (BENCH-097c, P1).** `allpos() :- forall R(x): x > 0`. The inputs are R(3), R(9), then
R(−2).
- `allpos` is provisional-true until R(−2), then **final-false** (Ex 11, Thm 24 negative).
- It is never final-true unless R is sealed.

**T8: the inverse curse on counters (BENCH-097d, P0).**
- PN-counter with increments to 12 and no decrements yet. `pn.value >= 10` must **not** be final:
  ANA-120 = NEVER-FINAL, and the runtime keeps it provisional.
- `pn.pos >= 10` is final-true at the 10th increment.
- A later decrement to 9 must flip `value >= 10` back to false. TEST-088 checks that it was never emitted as
  final.

**T9: 2P-Set finality (BENCH-097e, P1).** Insert a, b; delete b.
- "b ∈ set" is final-absent.
- "a ∈ set" is provisional-present forever ("never positively").

**T10: sealed aggregate (BENCH-097f, P1).**
- Election votes arrive from 5 voters, each followed by that voter's seal on `vote[election=e]`.
- `tally(e, count)` is provisional until all 5 seals are in, then final with the exact count.
- A threshold `tally ≥ 3` is final-true as soon as 3 votes arrive, before any seal.

**T11: finite-state FT with the four DFAs of [FT] Fig. 1 (BENCH-079, P1).** The ANA-122 algorithm must
report:
- (a) "contains an a": exactly the post-a sink is FT.
- (b) Two FT states: the accepting sink (two a's seen before any second b) and the rejecting sink (second b
  seen first). They have different values, which is the "different FT values" scenario.
- (c) "odd number of b's": **no** FT states.
- (d) Exactly one FT state: the accepting sink of the doesn't-start-with-b branch after two a's. The
  starts-with-b branch toggles parity forever.

These match the ★ marks in DISS Fig. 3.1. Text extraction shows three ★ in panels (a)+(b), zero in (c) and one
in (d).

Two more cases:
- 2PC per-transaction automaton: `committed` and `aborted` are FT, and `init` and `prepared` are not.
- Running product mod 2: `even` is FT via the homomorphic abstraction.

**T12: replicated DBSP view (BENCH-075, P1).**
- **Setup:** three replicas maintain `V(a,c) :- R(a,b), S(b,c), notin D(a)` incrementally (DBSP) over
  W2-replicated Z-set inputs R, S and D, with random inserts and deletes under chaos.
- **Expected:**
  - After quiescence, every replica's V equals the centralized naive evaluation (ENG-067) over Σ of all
    updates.
  - V is NEVER-FINAL.

**T13: OnceTree counter (BENCH-077, P2).**
- **Setup:** 15 nodes in a full binary tree; random ±1 updates at leaves; chaos on each edge.
- **Expected:**
  - Every node converges to the exact global sum.
  - Per-node metadata = degree + 1 entries.
  - The move-up, join, leave and reset operations keep the query result non-decreasing in *clock*, and preserve
    the final sum.

**T14: dot reuse after a crash (BENCH-078, P1, negative).**
- **Setup:** origin A with a non-durable `seq` and **no** incarnation bump crashes after sending (A,1..3), then
  restarts and sends new updates as (A,1..).
- **Expected:**
  - The receivers silently drop them. The test **must detect** the divergence, and it is the reason the
    incarnation or durable-seq rule is mandatory.
  - With the incarnation bump, no update is lost.
  - W3 with a reused seq and a different cumulative raises a `Conflict` hard error.

**T15: finality soundness under fuzzing (BENCH-098, P1).** Across 10⁴ random schedules with crashes, for
T5–T10:
- no fact emitted final-present is absent from the ultimate model;
- no fact emitted final-absent is present;
- two replicas never emit different final values for the same key. The components are commutative, so
  Prop 33 applies.

**T16: batch-job completion by seals and early thresholds (BENCH-099, P1).**
- **Setup:** a word-count stage with 4 input splits. Each split source emits a whole-split seal after its last
  record. The outputs are:
  - `counts(w, n)`, a `bag`-typed sum per word, insert-only;
  - `hot(w) :- counts(w, n), n >= 1000`, a threshold;
  - `total_distinct(k) :- k = count<w> counts(w, _)`.
- **Expected:**
  - `hot(w)` tuples are final the moment n reaches 1000 (POS-FINAL), before any seal.
  - `counts` and `total_distinct` stay provisional until all 4 split seals arrive, then are final (SEALED).
  - The stage reports "complete" exactly when all three outputs are final.
  - Two runs with different split interleavings produce identical final values.
- **Retracting variant:** a split may emit corrections, so `counts` becomes `zset`-typed.
  - `hot(w)` is **no longer** POS-FINAL: it is reclassified NEVER-FINAL until the seal.
  - A `final` annotation on `hot` becomes a compile error. This is Cor 20 applied to a job.

## 14. Errata and discrepancies found in the sources

- **[FT] Thm 36** (and DISS Thm 30): "(resp. domain-distinct-monotone)" should be "domain-distinct-antitone".
  The typo appears in both arXiv v1 and the LIPIcs camera-ready.
- **[FT] Prop 13:** "the free termination states are exactly the elements … at or above C". The "exactly" part
  implicitly needs every state below C to *reach* C. That holds in S∪ and in join-semilattices with C
  reachable, but not in an arbitrary inflationary S: a state that can never reach C is FT with value F. We
  implement the at-or-above direction as sound, and never use the converse to conclude non-finality.
- **[DISS] Algorithm 1** sends `agg` without its timestamp, although `merge` compares clocks. Messages must be
  `(timestamp, agg)`, as §4.3.2's prose says.
- **[DISS] §4.3.3 vs §4.7:** the implementation is "< 400 lines" in one place and "less than 300 lines" in the
  other.
- **[DISS] §5.2.1** writes `update(u, u⁻¹) = (T, 0)`, where [WR] §2.2 has `= 0`. The dissertation's form looks
  like an extraction or editing artifact.
- **[WR] Strawman 1:** PaPoC says "monotonically non-decreasing (∀x,y: x+y ≥ x)", which is really
  *inflationary*. The dissertation corrects the wording. The printed steps ("−x + x ≥ x … we get x ≥ 0 and
  −x ≥ 0") do not follow literally. The conclusion is still correct by the clean argument in §3.1.
