# S20 — user-defined lattices

The user (2026-10-06), after an explanation of LANGUAGE §11.8: "Add it". Scope as explained then: lattice aliases,
product lattices, `impl` blocks with method classes and the law harness; `extern lattice` and SMT proofs later.

## Plan

1. **blossom-lattice.** `Kind::Product(fields)` over `LatValue::Seq`: ⊥ is every field ⊥, merge and order are
   fieldwise, `reveal!` gives the struct of the fields' reveals, `of` builds a value from its fields (a morphism in
   each). No plain type lifts into a product. `laws`: the merge laws (associativity, commutativity, idempotence, ⊥
   identity, order agreeing with merge) and the class claims (morphism, bimorphism, monotone, antitone, threshold,
   stable after t) as checks over sample values.
2. **IR.** `LatticeCtor::Product { name, fields }` (nominal: two products with the same fields are different
   lattices). Every catalogue entry says how it is implemented (`LatOpImpl`): a built-in operation, a field read (a
   morphism), or a method (an IR function). A `stable fn m after t` has two entries: `m`, classed `Stable { after }`
   and monotone in its receiver, used only where the frontend found the guard `x.t()`, and `m!`, non-monotone, for a
   banged read. The validator checks every entry against its implementation. Engine, oracle and wire codec learn
   products.
3. **Frontend.** `lattice X = L;` is an alias of a lattice type. `lattice X { f: L, … }` is a product: its fields
   are lattices, a struct literal may omit fields (⊥), `x.f` is a morphism. `impl X { … }` on a product gives it
   methods; a method's class is its `fn` prefix, none is non-monotone. Method calls follow the bang rule by class
   (BLS0700/0701); a stable read needs its threshold guard on the same receiver in the same body, or a bang
   (BLS0703). Method bodies are pure functions and may `reveal!` freely.
4. **Law harness** (`blossom_verify::laws`, TEST-083). Products are proven by construction (merge, ⊥, order); each
   method claim is tested on generated values of small domains; a refuted claim is BLS0704 with its counterexample.
   The CLI runs it wherever it compiles a program; `blossom check --laws` prints each lattice's statuses.
5. **Corpus and examples**: BENCH-060a–c (the monotone cart), e05's cart; integration tests against the oracle.
