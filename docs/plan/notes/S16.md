# S16: sugar for trees and strings

Goal (user, 2026-10-05): make HTML pleasant to write, with sugar that is general rather than HTML-specific; the user
chose all four proposals (interpolation, nested heads with derived ids, fragments, record spread). Design:
docs/design/SUGAR.md; normative text in LANGUAGE §2.4 and §8.2.

## What was built

1. **Interpolation** `f"…{e}…{x:.N}…"`: the lexer splits the literal into text runs and holes (a mode stack, so holes
   nest); conversion joins the parts with `++`, each hole through `to_string` (or `to_fixed(N)`). `to_string` on
   `bool` and `String`, `f64.to_fixed(n)`.
2. **Child heads and spreads**: a head's block of child heads, each inheriting by name and type what it does not
   give; `..{name: value}` and `..map` write a row per field or entry.
3. **Tree literals**: `tree T { node …; props …; content …; }` (ui.bls declares `html`), and
   `emit html kind[id/key/pos](props) { children }`: node, props and content rows; parents and slots from the
   nesting; ids given or derived (`parent/kind.slot[key]`). `#id` was not possible: `#` starts a comment.
4. **Fragments** `fragment f(x: T) { items }`: called where a statement or a tree element stands; hygienic (a scope
   barrier hides the caller's variables; the parameters are bound from hidden temporaries and type-checked by an
   internal ascription).
5. **The examples rewritten.** Flappy: 208 → 101 lines of code (drawing 151 → 44; Eve: 104 total, 42 drawing).
   TodoMVC: 187 → 147 (the page 85 → 48), its items now a `for` inside the one page tree.

All of it expands, during resolution, into the statements and `if`/`for` blocks the language already had: analyses,
provenance, both evaluators and the inspector see ordinary rules.

## Decisions made on the way
- **A call-shaped child is an element (or a fragment call) only when it ends with `;` or opens `{` / has `[…]`**;
  otherwise it is content (`span { plural(n) }`).
- **Below an element, `for` no longer forces keys**: an element's id tells its descendants apart.
- **Fragment parameters are variable names** (BLS0436); the hidden temporaries are `arg$…` (lowercase).

## Known limits
- No source formatter exists yet (`blossom fmt` is unimplemented), so none was updated.
- A map spread among a tree element's properties is not supported (BLS0908).
- A fragment call in a tree statement with `to` is not supported (BLS0908).
- `to_string` on collections (Appendix B: every type) is still unimplemented; an interpolation hole of such a type
  reports it.
