## Rules (from the Kafka decisions)

- **No protocol-specific Rust in the broker.** The Kafka protocol and the broker logic are Blossom (K2).
- **Generic platform additions only** (K3): streams, functions, byte primitives, the `extern fn` standard library,
  blobs.
- **Test-only Rust is allowed** as an oracle (K5): the codec oracle and the simulator client harness. It never ships
  in the broker.
- **Standing rules.** Stubs hard-error with BLS0908 or a located runtime error. Commit per milestone. Mutation-check
  durability and consistency tests. An adversarial review closes the slice.

## Findings and deviations

### Item 1: functions (done)

What landed, crate by crate:
- **Frontend.**
  - `fn` items parse to `ItemKind::Fn`. Signatures are declared before any body, so a body may call a function
    declared after it.
  - Bodies resolve in their own scope, parameters first, with these rules:
    - `{ let …; e }` blocks bind new variables (shadowing); a `let` pattern is a name, `_` or a tuple of those.
    - Closures are allowed only as a method's argument in a function body.
    - Calls `f(…)` are checked for arity.
  - New diagnostics:
    - BLS0213: recursion, found as a call cycle.
    - BLS0214: a `let` block or closure outside a function.
    - BLS0215: a function reading a relation, `now()`, `tick()`, `self`, randomness or role members.
  - Not implemented yet; each is a BLS0908 hard error:
    - class prefixes (`monotone fn` …, LANG-182);
    - lattice-typed parameters and results (LANG-182);
    - generics, methods and `impl`.
  - Library methods resolve by the receiver's type in the solver (`plain_method`) and lower to `BuiltinFn::Lib`.
    Closures are typed through a side table, since a closure has no type of its own.
- **IR.**
  - `FnDecl` carries its variable table.
  - The validator checks function bodies against their own variables (`Cx`):
    - no scalars, `let` or closure outside a function;
    - each library call's argument types, closures included;
    - a call cycle, reported as recursion.
- **Oracle and engine.**
  - Each has its own implementation (`blossom-oracle/src/library.rs`, `blossom-engine/src/func.rs`) of calls,
    `let`, closure application and every `LibFn`.
  - A combinator over `range(lo, hi)` walks it without building it.
  - Bindings are scoped by copying the frame. Match patterns' equality tests now fold into the arm guard; before,
    they were an internal error.
- **Tests.**
  - `blossom-front` tests: every new diagnostic.
  - `tests/integration/tests/bls_functions.rs`: every library function and combinator, on random inputs.
    - The oracle and the engine must agree.
    - Every view must equal a direct Rust computation.
    - Mutation-checked: a wrong slice bound in the engine and a wrong `all` in the oracle each fail it.
  - Corpus: BENCH-024a and BENCH-024b (distance vector with `add_cost`) now pass on both backends and were
    ratcheted.

Bugs found on the way (fixed, each with a test):
- **`else if` lost its `else` branch** in the AST converter, an internal error. BENCH-062a reached it once functions
  resolved.
- **The engine used an internal error as a signal.** After a failed hoisted check, it treated a failed variable read as
  the sign of an unbound variable. Internal errors panic in debug builds, so `engine_planner`'s
  `a_hoisted_let_raises_only_for_complete_valuations` failed at f4dc858 too. The engine now checks boundness instead.
- **Equality tests in match patterns** were an internal error in lowering; they now fold into the arm guard.
- **A function used as a value** (`s.filter(joins)`, BENCH-054b) was reported as an unbound name. It is now BLS0908
  (LANG-124), since lattice operations take functions only after LANG-182.

Corpus after item 1: the whole corpus on both evaluators, and `--engine` on every area, show no new failures. The
known ones remain: lprov BENCH-309a/c and 311a–c, which do not compile (`LMap::lt!`, `sum_values`), and ldfi 130q
and 133d, as in S1.

Deviations from item 1's acceptance:
- **e06 still does not compile.** Its function now resolves and type-checks, but e06 also needs reliable channels
  (LANG-155), `partition by` and `sealed by` (LANG-020), `sealed` tests (LANG-207) and final outputs (LANG-212). None
  of those is function work, so e06 stays in `engine_examples`'s skip list with the reason updated.
- **New tests went into `tests/integration`, not the corpus.** The planned function cases (folds over ranges,
  `Option` decoders) are there because the corpus holds literature cases with FEATURES ids.
- **Not done yet: `error("…")` (BLSR010) and memoization of calls.** Both are in LANGUAGE §16.1/Appendix B.
  `error` is still a BLS0908 "calls of `error`". Memoization is an optimization. Neither is needed by S6's protocol
  code, which must not abort on client input.
- **The rest of Appendix B** (string, set and map methods beyond the ones above) is still a BLS0908 per method. The
  byte primitives come with item 2.

### Item 2: byte primitives (done)

- **What was built.**
  - Every read, patch and constructor for the 8- to 64-bit integer types, both signed and unsigned.
  - LEB128 and zigzag varints, read and written.
  - `to_utf8` and `from_utf8`, `Bytes::empty` and `Bytes::join`.
  - These are one `LibFn` family each (`BytesRead(IntTy)`, `BytesPut(IntTy)`, `BytesFrom(IntTy)`) and are typed in
    the validator.
- **Tests (`bls_functions.rs`, `byte_primitives_round_trip_and_agree_on_both_evaluators`).**
  - Random bytes and positions, and every integer type over its full range.
  - The oracle, the engine and a separate reference implementation must agree on every view: reads, patches,
    encode-then-decode round trips, varints with half the bytes continuation bytes, and UTF-8.
  - Golden varint vectors cover: empty, truncated, `u64::MAX`, overflow at the tenth byte, eleven bytes, and
    non-minimal zeros.
  - Mutation-checked: a looser overflow check in the engine's varint decoder, and a missing zigzag sign in the
    oracle, each fail it.

### Item 3: `extern fn` and the standard library (done)

- **Value level (`blossom-value/src/externs.rs`).**
  - `HostType` is a signature type independent of any program's type table. The registry's `TypeId` signatures
    were meaningless across programs.
  - `ExternRegistry::bind` compares a registration with a program's declared types.
  - The standard catalog is `STD_EXTERNS`.
- **Frontend.** `extern fn name(…) -> T = "path";` resolves to a function with an extern body. Anything off the
  catalog, or declared with a different signature, is BLS0216. Table functions, host types, host lattices and
  classes are BLS0908.
- **Evaluators.**
  - `blossom_ir::tick::bind_externs` checks, at load, that the registry provides every declared extern with its
    signature, and lists every problem (`EvalError::Externs`).
  - The oracle (`Oracle::with_externs`) and the engine (`EngineConfig::externs`) call the host function. A refusal
    is BLSR010.
  - `BlsSim::with_externs`, `SpecSim::with_externs`, `ClusterConfig::externs` and `ServerConfig::externs` carry
    the registry. The old constructors bind none, so a program with externs does not load through them.
- **Host library (`blossom-std-host`).** New areas `checksum`, `compress` and `hash`. Adding areas to the dispatch
  file is the plan change decision K3 made.
- **Tests.**
  - The host library, directly:
    - known answers: CRC-32C and CRC-32 check values, RFC 3720 vectors, SHA-256 of "abc", BLAKE3 of "";
    - every codec round-trips and is deterministic, with an exact output bound;
    - multi-member gzip and multi-frame zstd;
    - 1,600 malformed inputs, all `None` and none a panic;
    - a small bound stops 10 MB of zeros;
    - the registry equals the catalog.
  - End to end (`bls_functions.rs`):
    - on both evaluators, known answers and every codec round trip through `extern fn`;
    - BLSR010 at the same tick on both;
    - unregistered or mismatched host functions refuse to load, listing all 12. Mutation-checked by removing the
      engine's bind.
  - The frontend: BLS0216 for an unknown path and for a wrong signature.

### Item 4a: streams in the language and the evaluators (done)

- **Value level.** `Conn` is a value and type (`Value::Conn(ConnId)`, `TypeDef::Conn`), appended after the existing
  variants so no encoding changes. It is in the wire codec as a varint.
- **Syntax and frontend.**
  - `stream NAME: listen|connect;` declares the stream's relations (FOREIGN-PROTOCOLS §1.2a).
  - `Part` is the built-in enum `$builtin::Part`.
  - The event classifier treats stream events as events.
- **IR.** `StreamDecl`, `StreamKind`, `StreamEvent`, `HostOp`, `EventSource::Stream`, `RelClass::HostOut`, and
  `Program.streams`. The validator checks each stream's relations: classes, schemas, placement, and no sharing. It
  also checks that host requests are written only by async rules and never read.
- **Evaluators.** An async head into a `HostOut` relation goes to `TickOutput::host` / `StepOutput::host`, in the
  oracle and in the engine. The sync simulator records it per tick (`NodeTick::host`).
- **Tests.**
  - `bls_streams.rs` runs a Blossom line-echo server with scripted chunks on both evaluators. They must agree on
    every instance and host request. The writes must be exactly the complete lines, in order, with contiguous
    `seq`.
  - The same check runs over random chunking on up to four connections, 12 seeds.
  - Frontend tests cover every stream diagnostic.

### Item 4b: streams on the node and the real runtime (done)

- **Node (`blossom-node/src/streams.rs`).** This is logic shared by the runtime and the simulators.
  - `StreamInbox` turns what the host observed into each tick's stream events, with the ordering of
    FOREIGN-PROTOCOLS §1.2a:
    - `opened` alone in its tick;
    - one `data` per connection per tick, up to `max_stream_bytes`;
    - `closed` after the last `data`.
  - `SeqWriter` orders one connection's writes by `seq`. A gap holds later writes back; a duplicate, or a `seq` more
    than `MAX_SEQ_GAP` ahead, is a violation.
  - `host_request` decodes a released write, close or dial.
  - `Node::observe_stream` feeds the inbox. A tick's host requests are parked and released with it
    (`ReleasedTick::host`), after its WAL sync. `ReleasedTick::retired` lists the connections whose `closed` the tick
    delivered.
- **Runtime (`blossom-runtime/src/streams.rs`, `server.rs`).**
  - A listener per `listen` stream, at the address in `deploy.toml` (`streams = { name = "host:port" }`). A missing
    address, or one naming no listen stream, refuses to start.
  - `ConnId`s carry the restart count.
  - Per connection, a reader thread that reports `opened` before any bytes, and a writer thread that applies
    `SeqWriter`. A violation closes the connection, counts it and records the reason.
  - The host closes a connection:
    - when the program sends `close`;
    - when the tick that delivered its `closed` is released, after that tick's writes. So a half-closed peer still
      reads its replies.
    - when its write queue backs up.
  - Dials run on their own thread and answer with `opened(c, req, …)` or `failed(req, reason)`.
  - The engine stops taking data while more than 16 MiB of stream bytes wait for ticks.
- **Bitwise operators (LANG-084)** are now in both evaluators: `& | ^ << >> ~`. `>>` is arithmetic on signed types.
  A shift count outside the width is BLSR004. The Kafka decoder needs them for record-batch attributes, and so does
  the `order.bls` fixture. They are tested over every width against Rust, and for BLSR004 on both evaluators.
- **Parser.** A closure's body may be a `{ let …; e }` block, which decoders need.
- **Tests.**
  - `runtime_streams.rs`, over real TCP:
    - a Blossom line-echo server on six concurrent connections with random chunking;
    - a half-closed client gets its replies, then EOF;
    - a length-prefixed framing server, which decodes frames with a fold over `range`, under random chunking;
    - out-of-order writes are held and sent in `seq` order;
    - a duplicate `seq` closes the connection, with the recorded reason;
    - a connect-stream client falls back after a failed dial, then talks;
    - the configuration refusals.
  - `node_streams.rs`: stream writes and durability. Crash at every durable syscall of a workload with checkpoints,
    under lost, torn and mixed write fates, and every chunk whose acknowledgement was written is recovered.
    Mutation-checked: releasing a tick before its WAL append and sync (in the driver, as in S3) fails it.

### Item 4c: streams in the simulators (done)

- **Cluster simulator (`blossom-sim/src/cluster/streams.rs`).**
  - Pipes connect a node's stream to a Rust `StreamClient`, or two nodes: a connect stream dials `sim://NODE/STREAM`.
  - Bytes are split at random boundaries (`ClusterConfig::chunk_max`). Each chunk arrives after a random latency,
    never before the chunk ahead of it.
  - A node end writes through `SeqWriter`, and its writes leave only with their released tick.
  - Closes follow the runtime:
    - a client's close is a half-close;
    - a program's `close` gives the node end its own `closed`;
    - a released `closed` retires the node end;
    - crashes, partitions between node ends, `seq` violations and the nemesis (`ClusterConfig::stream_drops`) reset
      a connection.
  - `NoKvClients` stands in for runs without key-value clients.
- **`blossom sim`** takes scripted connections and chunks (`--open`, `--chunk` with escapes, `--close`). The script
  is checked against the runtime's ordering guarantees, and each tick's host requests print after its relations.
  Bytes print as `b"…"`, connections as `conn#N`.
- **Tests.**
  - `sim_streams.rs`, over 6 seeds each:
    - the echo server under random chunking: over 100 complete sessions, none cut;
    - the echo and framing servers under crashes (some mid-tick) and resets: no wrong byte ever. Every session a
      client half-closed ends with all its replies unless a fault cut it, and faults did cut some.
    - a node dials another node's stream and gets its echo.
  - Mutation-checked: delivering a pipe's chunks out of order fails the echo test.
  - `blossom-cli` checks the scripted chunks and the refusal of a misordered script.

### Items 5 and 7: the Kafka protocol library and the broker (the gate passes)

- **Library (`examples/kafka/`, all Blossom).**
  - `protocol.bls`: a cursor with fixed-width reads, uvarints, legacy and compact strings, and compact and nullable
    array lengths. A count is checked against the bytes left before any fold iterates over it. It also skips tagged
    fields and holds the encoders and `split_frames`, which rejects negative or over-100-MiB sizes.
  - `headers.bls`: request header v1/v2 and response header v0/v1.
  - `apiversions.bls`: v3–v4, and the v0-layout UNSUPPORTED_VERSION answer.
  - `metadata.bls`: v13.
  - `broker.bls` puts them together with `include`. It holds per-connection reassembly state, answers every complete
    frame of a chunk in one write, and closes on anything it cannot answer. Parameters: `NODE_ID`,
    `ADVERTISED_HOST`, `ADVERTISED_PORT`, `CLUSTER_ID`.
- **Language work this needed.**
  - Textual `include "file.bls"` (LANG-005). It used to be silently ignored, which broke the no-silent-stubs rule. It
    is now implemented in the module loader, with cycle detection (BLS0204). `include M;` and `.ded` includes are
    BLS0908.
  - Block bodies in match arms, with the comma optional after a block, like Rust.
  - The validator now types a `match` by a non-constant arm. A constant arm (`None`, `[]`) was ambiguous and made a
    false mismatch.
- **The gate (`tests/integration/tests/kafka_gate.rs`).** Three stock clients run against the broker as a node:
  - `kcat -L` lists `broker 1 at 127.0.0.1:PORT (controller)` and 0 topics;
  - `kafka-broker-api-versions.sh` prints `Metadata(3): 13 [usable: 13]` and `ApiVersions(18): 3 to 4 [usable: 4]`;
  - franz-go reads the metadata, falling back from ApiVersions v5.

  A missing tool skips its test with a printed notice.
- **Tools.**
  - kcat: `brew install kcat`.
  - Kafka: a Kafka 4.0.0 distribution unpacked into the main checkout's `.tools/`, which is gitignored.
  - Java: 21 (Java 17 or later is required).
  - Go: 1.26.

### Item 9: the adversarial review and its fixes

Four reviewers covered the Kafka code, the host functions, the byte streams, and the functions and library. Each
finding below was reproduced, fixed, and pinned by a test. Where the test is new, it was mutation-checked: undoing
the fix makes it fail.

**Kafka (`examples/kafka/`).**
- *Critical: one request could kill the broker.* `read_bytes` computed `pos + n` with a client-controlled `n`, so a
  tagged-field size or a compact string length near `u64::MAX` overflowed. That is BLSR004, and the node faulted.
  - Every length is now checked against the bytes left before any arithmetic.
  - Test: `kafka_codec.rs` `hostile_lengths_are_malformed_requests_not_faults`.
- *High: quadratic reassembly.* Each chunk re-joined everything pending, and `split_frames` stepped through the whole
  buffer, four bytes at a time.
  - Pending bytes are now a `Framer`:
    - parts that merge only with a part at most twice their size, so reassembly is O(n log n) and there are at most
      about 64 parts;
    - the size at which the front frame can be complete, `need`. Below it a chunk is only stored.
    - One join and one parse happen per completed frame. The parse looks for at most `2 + chunk/4` frames, since
      only the front frame starts before the chunk.
  - Test: `reassembly_finds_exactly_the_frames_however_they_are_chunked`: 100 random streams in random chunks, and a
    1 MiB frame in chunks of up to 256 bytes. It takes 0.15 s; with the old scheme it had not finished after 120 s.
- *Medium: a topic asked for by id got error 3.* Kafka's answer is UNKNOWN_TOPIC_ID (100) with a null name, and it
  ignores the name-only entries of such a request. The responses test now includes requests by id.
- *Low: a boolean byte other than 0 or 1 closed the connection.* Kafka reads any nonzero byte as true, and now so
  does the broker.
- *Refuted: "an unsupported version of an advertised API should get an error response".* Kafka's request parser
  throws `InvalidRequestException` for any version it lacks, except ApiVersions (KIP-511), and the socket server
  closes the connection. The broker does the same.
- *Kept, documented in `metadata.bls`:* Kafka collects requested ids and names into sets, so it drops duplicates.
  The broker answers each requested entry, so only a client that repeats a topic within one request sees a
  difference. Removing duplicates needs sorting or sets in functions, and a quadratic check would reopen a
  denial-of-service hole.

**Host functions (`blossom-std-host/src/compress.rs`).**
- *zstd window bomb.* The decoder allocates its whole window up front: up to 100 MB, whatever the output bound. The
  reviewer measured 4.26 GB of resident memory from a 64 KB input.
  - The frame header is now read first. A window larger than both the bound and 8 MB (RFC 8878's recommended
    decoder minimum) is refused before anything is allocated.
- *zstd returned corrupt data.* The content checksum and the declared content size are now checked.
- *zstd skippable frames* are now skipped, as RFC 8878 requires.
- *lz4 ignored trailing bytes and later frames.*
  - Each frame's extent is found from its block sizes, and the frame is decoded from exactly those bytes.
  - Every frame is decoded, and skippable frames are skipped.
  - Anything left over is malformed. The legacy format, which is a different format, is refused.
- Tests: new unit tests in `compress.rs` build frames by hand: a 64 MB window, a wrong declared size, a wrong
  checksum, skippable frames, and four kinds of trailing bytes.

**Byte streams.**
- *Simulator: a connection's opening was not ordered with what followed it.* The dialer could get the target's bytes
  or close, or a reset, before it knew the connection existed, which was an internal error. A client's bytes could
  likewise reach an end that had not been accepted yet.
  - `PipeConnect` and `PipeOpened` now go through the pipe's per-direction ordering.
  - A reset that comes before the connecting node knew the connection opened reaches that node as a failed dial.
- *Simulator: partitions leaked.* A dial made before a partition could still connect and carry bytes across it.
  Connecting and delivering now check the partition, and a partition resets connections that are still being made.
- *Simulator harness.* A refusal answered in the same call made a client that reconnected on refusal recurse until
  the stack overflowed. Refusals now arrive after a round trip, as a TCP reset does.
- *A `Conn` could reach another node, where it names a different client's connection.* A channel or a durable
  relation that can hold a `Conn` is now BLS0315.
- *A rule in one role could write another role's stream.* This faulted the node at release. Reads and writes of a
  relation placed at a role are now BLS0404 from rules placed elsewhere. This also closes the reviewer's aside that
  reading another role's table was a V3 internal error.
- *A write through stream `a` with stream `b`'s connection went to `b`'s socket.* `HostRequest` now carries the
  stream it came through. The runtime and the simulator refuse such a request, count it, and record the located
  error.
- *Runtime backpressure: one connection could make a node buffer about 2 GiB.* Backpressure is now in bytes
  (`[stream_limits]`, FOREIGN-PROTOCOLS §1.2):
  - a per-connection read-ahead, credited back when the engine takes the bytes;
  - a cap on everything queued;
  - the node's backlog;
  - a per-connection limit on unsent writes (bytes, not messages).
  - Stream reports have their own queue, so peers' messages and clients' requests no longer stall behind them.
  - `max_stream_bytes` is configurable.
- *A dial tried only the first address.* Every resolved address is now tried in order.
- *The runtime and the simulator disagreed on `seq` violations.* Both now close the connection. The peer gets what
  was already written, then the close; the program's `closed` carries the violation.
- *Smaller issues.*
  - A program `close` followed by the retire close counted `dropped_closed` twice; the retire close is now its own
    operation.
  - A dial that completes after the node stopped now closes its socket.
  - A node that halts or faults stops accepting connections and closes the ones it has.
  - A thread that cannot start after `opened` now reports the connection closed.
  - `blossom sim --open` now checks that the node runs the stream.
  - Scripted connection numbers are per stream.
- Tests:
  - `sim_streams.rs`: a greeting server with a client that redials constantly, under crashes, partitions and resets,
    12 seeds each; and a client that sends and closes in the same action as its connect, plus 1,000 or more
    refusals without recursion.
  - `runtime_streams.rs`: a write through the wrong stream; a dial of `localhost` that must reach the IPv4 listener
    (`localhost` resolves to `::1` first here).
  - `blossom-runtime` unit tests over real sockets: the read-ahead stops a reader until its bytes are taken (with
    the wait removed, 8 MiB queued); a duplicate `seq` shows up as the `closed` reason; the write limit.
  - Front-end tests for BLS0315 and BLS0404.

**Functions and the library.**
- *A match arm compared with an outer variable of the same name instead of binding a new one.*
  - In a function body, arm names now always bind afresh.
  - In a rule, an arm name the rule already binds is BLS0501: comparing and rebinding are both plausible readings.
  - This also removes the oracle/engine disagreement the reviewer found for rule bodies, which predates S6.
- *A non-exhaustive match was an internal error at run time.* It is now BLS0314 at compile time, naming a value no
  arm takes, for example `Some _` or `(…) false None`. The check is Maranget's usefulness algorithm over variables,
  tuples, enum and `Option` variants, `bool` and other constants (`exhaustive.rs`). An arm with a guard covers
  nothing.
- *`Node<R>` and `Node` parameters crashed the compiler (V8).* A function's parameters now keep their declared types.
  See the deferred item below for the general problem.
- *A closure passed to a lattice method crashed at lowering (V8).* It is now BLS0300.
- *`fold` evaluated its arguments in a different order in the two evaluators.* The engine now evaluates the receiver
  first, as the oracle does.
- *`range` and folds had no bound.*
  - Pure functions now have a step budget, `FN_STEP_BUDGET` = 10⁷ closure applications plus built `range` elements,
    counted from an outermost call to its return (LANGUAGE §16.1).
  - Past it the tick aborts with the new BLSR012, the same on both evaluators, and before any allocation.
  - The oracle now also counts a program error in a recursive stratum only at the fixpoint, as the engine always
    did. Before, a BLSR010 there could differ.
- *An out-of-range literal (`Bytes::from_u8(300)`) was an internal error.* It is now BLS0300, and so is `x + 256`
  for a `u8` `x`, in rules too.
- *A computed value in a `fact` was an internal error.* It is now BLS0908 (LANG-010): facts are folded at compile
  time, and this build folds only literals, constants and constructors of them.
- *Minor findings, all fixed:*
  - a `fn` may not take a built-in's name (`range`, `now`, `error`, …) or a stream's;
  - closure parameters are checked like `let` names, may not repeat, and may be `_`;
  - a name bound twice in a `let` or arm pattern is BLS0201;
  - an included file with a `program` header is BLS0201.
- *Left as specified:* a diamond include is BLS0201, since includes are textual (LANGUAGE §6.6).

**Checks.**
- The corpus on the oracle and with `--engine` gives the same counts as before the review:
  - core 193, lattices 47, async 36, net 3;
  - lprov: the known 309a/c and 311a–c failures;
  - ldfi: see the merge notes.
- `check-codes` and `check-layers` pass.

## Bugs

- **Role-typed `Node` inference is unsound at join points** (owner: `blossom-front` typeck; needs a design decision
  before a fix).
  - Unifying `Node<R>` with `Node` takes the meet, `Node<R>`, and refines the term. That is sound for a rule
    variable bound in two atoms, or compared with `==` in a rule body, because the body is a conjunction. It is
    unsound where the unification is a join of alternatives: `if`/`match` branches, collection literals, `push`,
    `concat`, `unwrap_or`, `fold`.
  - In a rule, `let x = if c { a } else { b }` with `a: Node<S>` and `b: Node` types `x` as `Node<S>`, and
    `send ping(1) to x` is accepted though `x` may be a node of another role.
  - In a function the IR validator catches the same thing, as a V8 internal error.
  - A fix needs join points to widen (take the lub) rather than meet, with the validator computing lubs for those
    library calls, or explicit casts (`a as Node`). That is a language change, deferred with this report.
- **`let x = e` over a bound `x` in a rule is not BLS0501**, as LANGUAGE §9.4 says it should be. It acts as the
  equality test. Owner: the resolver. Programs in the corpus may rely on it, so the change needs a corpus pass of its
  own.
- **An expression error on a valuation that a later negation would remove still aborts the tick** (from the host
  functions review). In `e(b, l), not big(l), let z = gz(b, l)`, both evaluators evaluate `gz` before the negation
  filters the row. They agree, and the same holds for BLSR004. Whether a hard error should require the whole body to
  hold is a semantics question for LANGUAGE §9 (owner: LANGUAGE, then both evaluators).
- **Replay across a codec upgrade.** Pure extern results are recomputed, not recorded in traces, so a trace replayed
  after a `flate2`, `ruzstd` or `lz4_flex` upgrade could diverge if a compressor's output changed. Owner: the trace
  design (record extern results, or pin codec versions per artifact).
