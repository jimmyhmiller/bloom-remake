## Rules (from the Kafka decisions)

- **No protocol-specific Rust in the broker.** The Kafka protocol and the broker logic are Blossom (K2).
- **Generic platform additions only** (K3): streams, functions, byte primitives, the `extern fn` standard library,
  blobs.
- **Test-only Rust is allowed** as an oracle (K5): the codec oracle and the simulator client harness. It never ships
  in the broker.
- **Standing rules.** Stubs hard-error with BLS0908 or a located runtime error. Commit per milestone. Mutation-check
  durability and consistency tests. An adversarial review closes the slice.

## Work items, in order

Each item is done when its acceptance holds and it is committed.

### 1. Functions (LANG-180)
- **Build:** frontend (resolve, typecheck, lower to IR pure functions); calls in the oracle and the engine;
  combinators with closures (`map`, `filter`, `filter_map`, `fold`, `all`, `any`); `range(lo, hi)`; `Option` and
  `Result` with their combinators; structs and enums in function bodies; memoization per input per tick.
- **Acceptance:**
  - e06 (wordcount) compiles and runs.
  - The corpus cases blocked on LANG-180 (8 in core, 6 in lattices at last count) are run and ratcheted.
  - New corpus cases for folds over ranges, and for decoders returning `Option`, pass on both evaluators.

### 2. Byte primitives (FOREIGN-PROTOCOLS §3)
- **Build:** the reads, writes, varints and patching built-ins, independently in the oracle and the engine.
- **Acceptance:**
  - Property tests (randomized) show every read and write round-trips.
  - Truncated and overlong varints are `None`.
  - Both evaluators agree on randomized inputs.

### 3. `extern fn` and the standard library (FOREIGN-PROTOCOLS §4)
- **Build:** the registry in `blossom-std-host`; `extern fn` in the frontend with registered-name checking; calls in
  both evaluators; CRC32C and CRC32; the gzip, snappy, lz4 and zstd codecs with an output bound; hashes.
- **Acceptance:**
  - Known-answer tests: CRC32C test vectors, and round-trips for every codec.
  - An unregistered name is a compile error.
  - Malformed compressed input is `None`, never a panic.

### 4. Byte streams (FOREIGN-PROTOCOLS §1)
- **Build:** the `stream` item (`listen`, `connect`); `Conn` and `Part`; event sources and host channels in the IR;
  node inputs and outputs; runtime listeners and dialers, readers, and a writer with `seq` order released after sync;
  budgets; deploy.toml `streams`; simulated byte pipes with random chunking and drops in the cluster simulator;
  scripted chunks in `blossom sim`.
- **Acceptance:**
  - A line-based echo server and a length-prefixed framing server, written in Blossom, work over real TCP against a
    Rust test client, and in the simulator with random chunking.
  - Writes are never released before their tick's sync, mutation-checked as in S3.
  - Out-of-order and duplicate write `seq`s are handled as specified.

### 5. Kafka protocol library in Blossom
- **Build:** `examples/kafka/` (or `std/kafka/` if it becomes a library):
  - the cursor type and primitive decoders;
  - compact strings and arrays, and tagged fields;
  - request header v2 and response header v1 (v0 for ApiVersions);
  - ApiVersions (the chosen version, plus the v0 fallback) and Metadata (the chosen version), as typed decoders and
    encoders.
- **Version choice:** capture what each target client (K7) sends against a real Kafka 3.7+/4.0 broker in KRaft mode
  (`kcat -d protocol`, the Java client with DEBUG logging, or a packet capture). For each API, pick the highest
  version every target client supports and uses. Record the table below.
- **Acceptance:**
  - Golden captures decode.
  - Encoded responses decode in the Rust oracle (item 6) to the intended structures.

### 6. The Rust codec oracle (test-only, K5)
- **Build:** a test crate (for example `tests/kafka-oracle`) using an independent Kafka protocol implementation (the
  `kafka-protocol` crate, or another reviewed one); it lives in `[dev-dependencies]` only.
- **Acceptance:** randomized differential tests.
  - Oracle-encoded requests decode in Blossom to equal structures.
  - Blossom-encoded responses decode in the oracle to equal structures.
  - This is checked for every supported API and version.

### 7. The broker program: ApiVersions and Metadata
- **Build:** a Blossom program with a `listen` stream. It runs:
  - the connection layer (reassembly, framing, reply order);
  - dispatch by api key and version;
  - ApiVersions and Metadata for a one-broker cluster with no topics;
  - error responses for anything else.
- **Acceptance (the S6 gate):**
  - `kcat -L -b <addr>` lists the broker.
  - `kafka-broker-api-versions.sh --bootstrap-server <addr>` (Kafka 3.7+/4.0) prints the supported versions.
  - Both run in a test, skipped only if the tool isn't installed, and in that case the test says so in its output.

### 8. The Blossom Kafka client
- **Build:** a Blossom program on the `connect` side that sends ApiVersions and Metadata and records the answers. It
  runs against the broker in the cluster simulator, beside the Rust oracle client.
- **Acceptance:** under the simulator, with random chunking and connection drops, both clients see the same answers.

### 9. Close the slice
- A corpus pass on both evaluators, and the workspace tests.
- An adversarial review, with its findings fixed.
- These notes completed; a merge commit "Slice 6: foreign protocols in Blossom".
