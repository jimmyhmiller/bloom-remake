# M1.1 — Workspace skeleton, tooling, blossom-base and the blossom-value type surface

## What was built

**Workspace root.** `Cargo.toml` (resolver 3, glob members `crates/*`, `systems/*`, `tests/integration`,
`tests/codegen-corpus`, `xtask`; `exclude = ["fuzz"]`; edition 2024, rust-version 1.96, `publish = false`; the
workspace lints of the spec; `overflow-checks` in every profile, `panic = "abort"` in release, build-override
opt-level 2; every internal crate and the light external crates in `[workspace.dependencies]`, versions verified by
building). `rust-toolchain.toml` (1.96.0), `rustfmt.toml`, `clippy.toml` (the ARCH-19 disallowed types and methods,
test allowances), `deny.toml` (the §1.2 license allowlist, advisories, the aws-lc ban), `.config/nextest.toml`,
`.gitignore` (`/target*`, `/.tools`, `/datasets`, fuzz outputs), `.github/workflows/ci.yml` (fast tier on Linux and
macOS, then cargo-deny). A clean `cargo build --workspace` takes 15.6 s (Apple M2 Max, 12 cores; informational).

**Crates.** All 35 crates of ARCHITECTURE §1.2, `xtask`, ten `systems/*` (`blossom-sys-<name>`),
`tests/integration` (`blossom-integration-tests`) and `tests/codegen-corpus`. Every manifest pre-declares exactly the
internal edges of `xtask/layers.toml` (checked by script during this WP). Pre-declared modules: `blossom-syntax`
(8), `blossom-front` (16), `blossom-std-host` (29 areas, each with `register`, plus `register_all`/`registry`), the
CLI (24 subcommands) and xtask (14 tasks). Every placeholder names its FEATURES id and the owning WP from plan.json
(verified against every `owns` list). `blossom-testkit` declares the `corpus` and `molly_parity` libtest-mimic
harnesses, which report zero tests. `fuzz/` is its own workspace with the nine targets, each panicking
`fuzz target <name> is not implemented yet (WP <id>)`.

**blossom-base (complete; frozen after M1).**
- `idx`: `define_idx!`, `Idx`, `IndexVec` (checked push and conversions, `get_or_bug`, `pick2_mut`, `pop`,
  `truncate`, `resize_with`, `try_extend`, serde as a plain sequence), every id of ARCHITECTURE §2.1 plus `OpId`.
- `span`: `Span`, `LineCol`, `SourceDb` (UTF-8 checked, ≤ 4 GiB, line/column in Unicode scalars, `span_text`,
  `line_text`), the thread-safe `Symbol` interner (ordered, hashed and serialized by text), `QualName`,

- `diag`: `Diagnostic`, `Severity`, `Label`, `FixIt`, `TextEdit`, `Diagnostics` (JSON, `--strict` escalation,
  canonical sort), and the single BLS0908 constructor `Diagnostic::not_implemented` / `from_unimplemented`.
- `error`: `FeatureId` (well-formedness checked), `Unimplemented` (the exact shape and message of §12.1),
  `InternalError`, `unimplemented_feature!`/`unimplemented_error!` (the feature id is checked at compile time), and

- `codes`: `REGISTRY` of all 114 codes (110 from LANGUAGE §20, BLS0908/BLS1009/BLS1010/BLSR011 from §0.3, BLS1003

## Deviations

- **`Symbol` is an interned `&'static str`, not a `define_idx!` id.** ARCHITECTURE §2.1 lists `Symbol` among the
  `define_idx!` ids; the PLAN spec requires that symbol ids never be observable and that `Symbol` order by text.
  A pointer to interned text satisfies both without a lock on every `as_str`. Nothing in the design indexes by
  `Symbol`.
- **`Diagnostic::primary` is `Option<Span>`.** Some diagnostics have no source location (BLS0908 at load time,
  BLS0204 for a missing file).
- **`CodeInfo` has two more fields:** `also` (other crates allowed to construct the code: the oracle for every
  BLSR code, because ARCHITECTURE §11.2 has it report the engine's codes; a few front/analysis splits) and
  `origin` (LANGUAGE §20 or the §0.3 amendment), which check-codes compares with the documents. BLS0908 is owned
  by `blossom-base`, whose `Diagnostic::not_implemented` is its only constructor, so every crate reports it
  consistently.
- **CLI subcommands take `run(args, &Context)`** instead of `run(args)`. The context carries start-up state
  (global options, logging), so M6.3 and M12.4 can add global options in `src/common/` without editing the frozen
  `main.rs`.
- **`blossom_std_host::registry()` returns `Result<ExternRegistry, ValueError>`**, where the spec says
  `ExternRegistry`: a path registered by two areas is an error, and library code may not panic.
- **`blossom-base` depends on `siphasher`** (ARCHITECTURE §1.2 lists it only for blossom-value), because
  `RuleLabel::hash` (SipHash-1-3, §2.1) lives in base.
- **License allowlist contradiction.** ARCHITECTURE §1.2 names `xxhash-rust` for blossom-value but its allowlist
  omits the crate's license, BSL-1.0. Decision: keep the named crate and allow BSL-1.0 for `xxhash-rust` only
  (`deny.toml`, `docs/design/DEPENDENCIES.md`), as §1.2 does for MPL-2.0. This needs a DECISIONS.md line at the
  M1 gate; M1.1 does not own DECISIONS.md.
- **Additions beyond the listed surface** (all additive): `Value::UnknownVariant` (LANG-261 keeps an unknown
  variant's number and bytes); `RecordTarget`, so one `RecordBuilder` serves both a `ValueStore` and a `WordSink`;
  `ScalarKind`/`NicheScalar` naming the direct encodings; `IdxOverflow`; the `IndexVec` and `DetMap`/`DetSet`
  helpers listed above; `blossom_std_src::{lookup, StdModule, rejected}`.
- **Feature ids of the value stubs.** Each names the FEATURES id closest to the function, and its detail names WP
  M2.1: encodings ENG-020 (u32/u64 lanes), fingerprints ENG-032, PRF SEM-084, decision streams DIST-032, set-hash
  elements ENG-120, BLAKE3 digests TEST-010 (the program digest of the trace header), the reference store LANG-023.
- **`check-sans-io` also forbids `std::os::unix::net`** (Unix-domain sockets, the rest of `std::net`) and checks
  test code in the node crate too, as the spec's "`crates/blossom-node/src/**`" says.
- **Extra CI fragment `scripts/ci.d/45-corpus-lint.sh`** (fast tier): validates every corpus area's manifests with
  the plan's `tests/corpus/tools/check_manifests.py` until M5.2 deletes that checker; then it prints that
  `xtask corpus --lint` (50-corpus.sh) has taken over and passes. This checks the merged corpus at the M1–M4
  gates.
- **`ExternRegistry` has no signature-check API yet.** Signatures are `FnDecl` types from `blossom-ir`, a crate
  above `blossom-value`; M2.1 owns the crate and designs the check (value freezes only after M2).
