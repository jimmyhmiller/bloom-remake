# M2.4 — blossom-sat

## What was built

Implemented the `SatSolver` interface and a stable literal representation, production CaDiCaL via RustSAT, a pure-Rust BatSat backend, bounded exhaustive oracle, and DIMACS recorder. Backends support incremental clauses, assumptions, model inspection, and failed-assumption cores with explicit result-state errors. Resource limits yield `Unknown` instead of pretending a verdict. Added balanced equivalence totalizers, including weighted thresholds. Deterministic cross-backend conformance checks random CNFs, assumption cores, incremental additions, and enumeration; cardinality tests brute-force every assignment and test both polarities of output literals.

Post-review fix: exhaustive assumption-core minimization now consumes the same time/conflict budget as the solve, and returns `Unknown` if exhausted.

Acceptance passed: `scripts/wp-check.sh blossom-sat`, batsat-only tests and clippy, and all required named tests.

## Deviations

- `generalized_totalizer` uses a dense unary threshold vector rather than sparse weighted buckets. This retains the documented `Vec<Lit>` index-by-threshold API and exact weighted semantics. Large thresholds can require large allocations; allocation failure is an explicit `EncodingTooLarge` error.
- BatSat's public API has no setter for its internal conflict budget. The callbacks count learned clauses from propositional conflicts and stop when that count reaches the requested budget. A root-level contradiction may finish with `Unsat` before the budget callback, which is a conclusive verdict. Time and conflict limits are checked through the same callback. This is a conservative resource limit, not a proof of an exact conflict count.
- The DIMACS backend is a recorder. Its `solve` returns a clear error; a `.cnf` file must be passed to an external solver.
