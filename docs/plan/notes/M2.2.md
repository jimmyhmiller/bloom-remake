# M2.2 — Dedalus core IR, builder, validator, printer, digest and projection

## What was built

The `blossom-ir` crate now defines the core program, physical plan, strata, observation and spec data models with serde/postcard support. `IrBuilder` records construct membership and rejects duplicate declarations. `ValidatedProgram` checks V1–V12, caches a canonical BLAKE3 program digest, and projects rules and reachable declarations to a role. The IR printer emits stable declaration and rule order with construct labels; expressions identify referenced functions, relations, lattices and sites by stable names. `PhysicalProgram::digest` records the complete executable plan, including profile and ABI.

The validator reserves the root user relation name `violation` and requires `HeadMode::Violation` to target a generated `$violation` relation. This resolves `BUGS.md#26` at the IR boundary. The M3.5 resolver must produce its normal reserved-name diagnostic for the same spelling.

Validation: `scripts/wp-check.sh blossom-ir` and the M2.2 `scripts/require-tests.sh` command passed. Tests include a proptest across every dense ID space, span invariance, type and constant reorderings, role send/receive projection, all twelve validator invariants, builder ownership, postcard roundtrips for programs, specs and plans, plan profile digest changes, time-varying scalars and a reviewed printer snapshot.

## Deviations

- The builder returns `Result` from `intern_const`, `begin_construct` and `RuleBuilder::var`, rather than the infallible signatures sketched in ARCHITECTURE §2.9. `IndexVec` can report ID overflow; returning an error preserves that failure instead of panicking.
- `ProgramErrorRecord.code` remains the specified `&'static str`; its custom postcard decoder resolves it through the registered diagnostic-code table so a decoded record does not leak a string or accept an unregistered code.
- The built-in violation relation uses a generated `$violation` suffix to keep it distinct from user declarations. A root declaration named `violation` is reserved. This is the explicit resolution of `BUGS.md#26`, and should be reflected in the surface resolver in M3.5.
- The physical plan's structural helper types omitted from ARCHITECTURE §3.1–3.2's Rust excerpts are defined here from their documented roles. M3.2's validator and the planner will be the first consumers that exercise every field together.
