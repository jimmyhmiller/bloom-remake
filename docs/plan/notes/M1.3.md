# M1.3 — Golden corpus II: lattices and lattice provenance (BENCH-050–079, BENCH-300–313)

## What was built

126 golden-corpus cases, each a directory with `manifest.toml` (schema v1, PLAN §5), a self-contained `program.bls`
(a `program NAME version 1;` root, no `std::` imports) and, where a verifier runs, a `spec.bls`:

- `tests/corpus/lattices/`: 75 cases for the 26 P0/P1 ids of FEATURES §11.2 (BENCH-050–079; BENCH-065 and BENCH-077
  are P2 and belong to M15; BENCH-071/072 do not exist).
- `tests/corpus/lprov/`: 51 cases for R11/G1's T1–T14 (FEATURES §11.10, BENCH-300–313).

Every expected value comes from the literature: FEATURES §11 item text, R04 §12 T1–T24, R11 §7 T1–T14, R13 §12 T1–T14
and the programs and data they quote (Bud `tc_lattice.rb`, SoCC'12 figures, bud-sandbox, the δ-CRDT catalog, Dolan,
Ross–Sagiv/FLP). No value was taken from running an implementation (none exists). Where a source names a test but
gives no data, the data is re-derived, the manifest says `derived = true`, and the derivation is in its `notes`. Every
backend starts `unimplemented` with `unimplemented` = the case's `features` and `until` computed by PLAN §5.4 from
`docs/design/plan.json`.

## Conventions these manifests use

Schema v1 fixes the keys but not every value shape. M5.2 (which owns `manifest.toml` for schema-level fixes) should
read these as the shapes the M1.3 cases were written against:

- **Nodes.** `[deploy]` names follow the source (`v1`…`v5`, `c`, `r1`, `A`, `B`…). Spec node names must be
  SCREAMING_CASE (BLS0211), so LDFI/ASP/sim-spec cases use `V1`, `C`, `R1`…, and `[expect_ldfi] nodes` and falsifier
  atoms use the spec's names. A roleless program deployed on several nodes gives each node `role = "Node"`.
- **Spec targets.** `spec X for r#program { … }`: a program root's module path is its file path, and `program.bls`'s
  is `program`, a hard keyword, hence the raw identifier (LANGUAGE §2.3, §17.2, E10).
- **Rows.** A cell is a one-column relation; lattice columns are written in their revealed form (sets and vectors as
  arrays, maps and `VClock`s as `[k, v]` pairs, products as their fields); `Lex` values use the
  `{ blossom = 'Lex::of(…)' }` escape; `Option` values use `{ some = v }`. A ⊥ cell is an absent row.
- **`[expect_analysis]`.**
  - `points_of_order = [{ at = "<handler label or view name>", op = "<bang call or keyword>" }]`, the exact list.
  - `strata = { rel = n }`; `calm_labels = { output = "Bot" | "A" | "N" | "D" }` (ANA-023).
  - `confluent = { rel = verdict }` with verdicts `certified`, `confluent_not_certified` (ANA-143), `not_confluent`,
    `inconclusive`. In a sim case (307b) the verdict is the simulator's ultimate-model/confluence verdict (M8.2).
  - `finality = { output = ["CLASS", …] }` (ANA-120), or for ANA-122 components
    `{ "inst.output" = { class = "FINITE", ft = { state = value }, abstraction = "…"? } }`: the exact FT table.
- **`[expect_verify] bounds`** carries the failure-spec bounds plus, for ASP enumeration, `counterexample_models`,
  `schedules` and `ultimate_models` where R11 gives the counts.
- **`[[expect_diag]]`** lists the errors a case is about. Warnings (BLS1xxx lints, BLS0505, BLS0701) are not
  listed and were not meant to be asserted absent. Diagnostics that `blossom-analysis` produces (BLS0502, BLS0503,
  BLS0702, BLS0705; ARCHITECTURE §13.1) are expected from `[backend.analysis]`; frontend diagnostics (BLS03xx,
  BLS0706, BLS0707) from `[backend.compile]`. Where a cycle has several constructs the line is not pinned.
- **Group-typed channel columns.** The Z-set cases replicate through `channel c(key…, w: Z) key(key…)
  exactly_once(dots | cumulative)`. They assume what LANGUAGE §11.10's IR (`$unwrap`, `$entries`) and R13 §7.3's
  ZBatch imply: a tick's updates are summed per key at the sender (a zero sum sends nothing), and the receiver sees the
  tick's unwrapped delta, one row per key with the summed weight of the newly applied dots.
- **Crash view.** `.bls` LDFI cases use `crash_view = "frozen"` (PLAN M1.3 scope, CR-20).

## Deviations from the spec, and why

1. **BENCH-078 and BLSR011.** PLAN's M1.3 scope says "BENCH-078 expects BLSR011". ARCHITECTURE §0.3 L1 and §4.6 define
   BLSR011 as the built-in wrapper's check for a dot reused with a different payload, but the built-in wrapper cannot
   reuse a dot from any surface program or manifest fault: its seq is durable or scoped by the incarnation, nothing is
   released before the durable commit (Invariant R, SEM-072), and a missing data directory refuses to start
   (ARCH-25). So R13 T14's "W3 with a reused seq and a different cumulative raises a Conflict" is written with the W3
   lattice spelled out (`078c`), where the conflict is the `LPoint` conflict LANGUAGE §20 defines: BLSR006. LANGUAGE
   and ARCHITECTURE outrank PLAN (§2.7). BLSR011 itself is M8.6's to test (PLAN line "Wrapped … + BLSR011").
2. **Analysis diagnostics under `[backend.analysis]`.** ARCHITECTURE §13.1 assigns BLS0502/0503/0702/0705 to
   `blossom-analysis`, M5.2's compile backend is "frontend only", and its analysis backend reports "stratification
   errors with codes". `067b`, `068a–c`, `073c` and `305b` therefore use `[backend.analysis]` with `[[expect_diag]]`
   (which `check_manifests.py` accepts) rather than `[backend.compile]`. Sibling corpus WPs that put these codes under
   `compile` would need the same move; M5.2 owns the schema-level fix either way.
3. **No `.ded` twins.** No case in this range has a plain-Dedalus source: R11's T1–T14 are Dedalus^L (lattice-valued
   columns), which the Molly `.ded` dialect cannot express, and the rest come from Bud, Anna, Hydro and R13. (T14's
   set-valued form `p(b) :- count<X> p(X) > 0` would be rejected as unstratifiable in Dedalus; that is not what
   BENCH-313 asks.)
4. **What schema v1 cannot express**, left to the owning implementation WPs and recorded as follow-ups:
   R13 T1's instrumented check that payload applications equal the number of distinct dots; R13 T1/T2's chaos
   parameters (1–4× duplication, 30% or 50% loss, anti-entropy every 5 ticks for the built-in W3). The chaos cases
   (`073b`, `074a`, `075a`) script drops of first sends with `[[fault]]` instead, and do not set `swarm` (swarm may
   crash nodes, which would break "converges in every seed").
5. **BENCH-060's "at most one response per distinct summary"** is a sender-side resend suppression (DIST-007) that
   must not be observable: under Dedalus semantics the level-triggered response is re-derived every tick, and the
   client keeps one distinct receipt per session (`060a`). No `expect_send` count is asserted, because the oracle
   counts every re-derived send.
6. **BENCH-063's causal CRDTs** (R04 T17: AW-Set via DotMap, EW-Flag, MV-Register via DotFun). LANGUAGE §11.5 names
   `Causal<…>` but gives no constructor or update operation, so `063c/063d` build them from grow-only dot sets with
   tombstones for observed dots, which has the causal versions' observable semantics. `063d` asserts convergence
   (replicas agree) rather than values, because the final values of causal CRDTs depend on causality.
7. **BENCH-307's "inconclusive or limit" result** is the `confluent = { c = "inconclusive" }` entry of the sim case
   `307b` (no quiescence and no lasso: M8.2 reports inconclusive, never confluent), plus POS-FINAL for the threshold
   output in `307c`. Schema v1 has no dedicated ultimate-model key.

## Judgement calls (for the M6.7/M8.8 corpus triage)

- **Re-derived data** (`derived = true`, derivation in each manifest): 051a–c/e–f, 052c (the Variant's `next_hop` for
  extended paths), 053a (graph with a −1 cycle), 054a/b, 055a/b, 056a/b, 057a–e, 058a–c, 059a/b, 060a–c (routing of
  R03 T20's simple_workload), 061a–c (bud-sandbox scenarios re-staged in rounds), 062b, 063a–d, 064a/b, 066a, 067b/c,
  068a–c, 069a, 070a, 074b/c, 075a, 076d, 078a–c, 079a–f, 312d.
- **`059a/b`: `LDom::of(version, value)`** is assumed by analogy with `Lex::of(k, v)`; LANGUAGE lists `LDom` with no
  constructor. `059b`'s BLSR006 holds whichever way LDom stores two pairs with one version, because the view reads
  `value!()` in the arrival tick.
- **`073e`, `078a`: `#[nondet(…)]` as the way to "force" an unwrapped group payload or a hand-written dedup through
  ANA-015.** FEATURES BENCH-073 and R13 T1 say the negative variant is "forced through with `nondet`"; LANGUAGE §20
  states BLS0307 with no exception. If the front end does not accept the override, these two cases fail at compile
  time; the fix is a LANGUAGE clarification, not a changed expectation.
- **`076d` (Dolan Fig. 1a/1b)**: the figure was not read; the scenario is R13's summary made concrete with a concurrent
  remove at the other replica (remove-and-undo at A leaves the element present; no remove at A leaves it absent).
- **`079a–d`**: the four DFAs are re-derived from R13 T11's descriptions (the ★ counts 1+2, 0, 1 match); `079e` uses
  the standard 2PC per-transaction automaton; `079f` expects ANA-122 to find the abstraction `p % 2` itself, because
  LANGUAGE has no syntax to declare one.
- **`079e`**: the FT table's values are the `Decision` variants written as strings.
- **`300b` `runs_max = 11`**: R11 says the first hypothesis round is exactly the 10 falsifiers, so a find-all run needs
  the failure-free run plus 10; a first-counterexample run needs fewer, so 11 is an upper bound either way.
- **`300c`**: R11 restricts crashes to voters; here `pre` requires the coordinator to be up, which excludes exactly
  those runs.
- **`308d`, `300d`, `312d`**: the ASP model counts are R11's (clingo); `312d`'s bounds (delay ≤ 2, horizon 8) are this
  WP's choice for the SEM-108 differential instance.
- **`061c`**: the report relation is `causal_violation`, not `violation`, which the IR uses for invariant and seal
  violations.
- **`064a`**: `calm_labels` treats `checkout` (through the negation of `in_cart`) as D and the two threshold outputs
  as A.

## Bugs

These are gaps in the normative documents found while writing programs to them (there is no code yet); each names the
reproducer case and the WP whose surface is affected.

1. **LANGUAGE §11.5: `LDom<V, L>` has no constructor.** Reproducer: `tests/corpus/lattices/BENCH-059a-versioned-kvs-ldom`
   (`emit store(k, LDom::of(ver, set[v]));`). Affects blossom-lattice (M4.6, LANG-132) and front typing (M4.5).
2. **LANGUAGE §11.5: `Causal<DotSet | DotFun<V> | DotMap<K, L>>` have no constructor or update operation**, so the
   δ-CRDT catalog cannot be written with them (`BENCH-063c` uses dot-set compositions instead). Affects M4.6
   (LANG-134) and M4.5.
3. **LANGUAGE §11.10: the semantics of a keyed group-typed column on an `exactly_once` channel is unstated** (summing
   per key at the sender and within a delivered batch; what a receiving atom `c(k, w)` ranges over), and so is the
   surface for reading the entries of a `ZSet<T>` payload. Reproducer: `BENCH-073a` (`channel count_delta(item:
   String, w: Z) … key(item) exactly_once(dots)`; `on count_delta(item, w) { emit counts(item) weight w; }`). Affects
   front lowering (M5.3/M6.4) and the wrapper (M8.6).
4. **LANGUAGE §20 / ANA-015: whether `#[nondet("…")]` downgrades BLS0307 and the ANA-015 rejection is unstated**,
   while FEATURES BENCH-073 needs the negative variant "forced through with nondet". Reproducer: `BENCH-073e`.
   Affects M4.5 (boundary types) and M5.6.
5. **`violation` is not a reserved relation name**, but the IR uses a relation of that name for invariant and seal
   violations (LANGUAGE §14.4, §17.1). A program declaring `table violation(id: u64);` would collide with it.
   Affects the resolver (M3.5, BLS0201's reserved names) or the IR's naming of that relation (M2.2).
6. **ANA-122 has no way to declare a homomorphic abstraction** (R13 §9.5 step 4). Reproducer: `BENCH-079f` (running
   product mod 2). Affects M6.6.
7. **Schema v1 has no key for sim ultimate-model expectations**, no duplication fault class (ARCHITECTURE §0.2 makes
   it opt-in) and no wrapper counters. `307b` uses `[expect_analysis] confluent` for the ultimate-model verdict.
   Affects M5.2 (manifest types) and M8.2 (sim backend).
