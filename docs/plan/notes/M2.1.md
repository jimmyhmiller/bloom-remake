# M2.1 — blossom-value encodings and reference model

## What was built

Completed direct scalar encodings and 32/64-bit lane selection; checked invalid words instead of truncating. Added type-directed proptest strategies, stable xxh3 Merkle fingerprints with checked vectors, versioned SipHash-1-3 PRF/seeds/independent streams with checked vectors, BLAKE3 digests and incremental 128-bit set hashes. Implemented the complete type-checked reference value store for scalar and interned values and record building for typed collections, an exact host-function signature binding API, 1–256-bit modular arithmetic/literals and ring intervals. Bounded recursive `Value`, `LatValue`, and `GroupValue` serialization and deserialization at depth 128; a crafted nested postcard payload now returns an error instead of overflowing the stack (BUGS.md#1).

Post-review fix: a legal but uninhabited enum now makes the type-directed generator return an explicit error instead of panicking.
The M1 `NicheScalar::EnumTag` API remains available; type-directed selection uses a new bounded variant so an optional tag fits a 32-bit lane only when its maximum leaves room for the `None` niche.

Acceptance: `scripts/wp-check.sh blossom-value` and every M2.1 required named test passed after implementation. The crate is also exercised by all-feature unit tests, property tests and strict serde roundtrips.

## Deviations

- `ExternRegistry::bind` accepts the value-level `ExternSignature` extracted from a source `FnDecl`. The value crate cannot depend on `blossom-ir`, so it cannot take `FnDecl` directly. Untyped registrations remain useful for direct tests but are rejected by bind.
- `RefValueStore::record` builds composite rows whose child type information is in `TypeTable` (tuple, struct, enum, vector, set, map, option). Lattice/group values have separate internal representations and are interned through `intern_value`.
