# S14: TodoMVC in the browser

Design: docs/design/BROWSER.md (decisions B1–B5, user 2026-10-05). Goal: show Blossom is general-purpose, Eve style.

## Plan

1. The host core, natively (`crates/blossom-web`): compile in memory, rounds through the engine, the page diff,
   persistence; a counter end to end in native tests. String functions.
2. In the browser: the wasm build, `web/host.js`, the page; the counter, then TodoMVC with the official CSS; the
   Playwright gate.
3. The `why` inspector.
4. The live editor.

## Progress
- **Slice 1, the host core** (`crates/blossom-web`): `compile` from sources in memory (the driver's
  `compile_with_loader`, with its analyses), an `App` that runs an event until its effects settle (a write takes
  effect the next round, so the host steps without events while the state changes, at most 1000 rounds), the page
  diff keyed by element id (`page.rs`), durable tables saved and restored as JSON with the runtime's schema hashes
  (`store.rs`), and the wasm-bindgen API (`wasm.rs`; the wasm build is 5.1 MB with the compiler). Inputs are listened
  to only when a rule reads them. Strings: `s.trim()`, `n.to_string()` (Appendix B; `++` and `len` were there).
  `examples/web/ui.bls` (the interface), `examples/web/counter.bls`; native tests drive both.

- **Slice 2, in the browser:** `scripts/build-web.sh` (the wasm module with a 64 MiB stack, wasm-bindgen, the example
  sources into `web/pkg/`), `web/host.js` (patches through an id → node map, a text node before an element's children,
  delegated listeners for the inputs the program reads, blur from `focusout`, events queued while patches apply,
  `localStorage` after every event), `scripts/serve-web.mjs`. **TodoMVC** (`examples/web/todomvc.bls`, ~250 lines of
  Blossom) with the official stylesheet (`web/todomvc.css`, todomvc-app-css 2.4.3, CC-BY-4.0 with attribution):
  the whole spec natively through the host (a model DOM) and in headless Chromium (`tests/web`, Playwright 1.63:
  adding, toggling, toggle all, editing with Enter/Escape/blur/empty, destroy, routing with back, persistence).
- **Slice 3, the `why` inspector** (`crates/blossom-web/src/why.rs`): the host keeps the last 500 rounds (the state
  each started from, its events, the rows it wrote); the oracle re-runs a round with capture on when asked. An
  element's `elem`/`attr`/`text` rows are explained by their firings, through views, down to the round's event, and a
  table row by the round that wrote it (its write's firing); generated relations are provenance-transparent, and an
  expansion's rule with no statement of its own (an upsert's write) is credited to the user rules that fed it, so a
  todo reads "written in round 7 by rule `toggle`" ← `change("toggle-1", true)`. Repeated facts say "explained
  above". In the page: "Why?" toggles inspect mode (hover outlines an element with its id; a click explains it and
  the app gets no input; Esc leaves), the tree shows beside the app and follows the page.
- **Slice 4, the live editor:** "Source" shows the app's files; Run (or Ctrl-Enter) compiles in the page and, if it
  compiles and starts, replaces the running program, keeping each durable table whose schema is unchanged (a changed
  one starts empty, with a note). Diagnostics list with positions; clicking one selects its span (the host gives
  UTF-16 ranges). An edit is kept in `localStorage` across reloads; Revert goes back to the app's own source. The
  focus stays in the editor across a run.
- **Tests:** native (`crates/blossom-web/tests/host.rs`, 7: the counter, persistence, errors with ranges, TodoMVC's
  spec, the inspector's explanations and a restored row); Playwright (`tests/web`, 13: the counter, TodoMVC's spec,
  the inspector, the editor's run/reload/revert, a failed compile, a schema change).

## Known issues found
- **Type errors are reported at a later use.** In TodoMVC, `plural(f)` with `f: String` (from `filter(f)`) reports
  "type mismatch: u64 and String" at `link_class(f, "all")` and the other uses of `f`, not at `plural(f)`: inference
  seems to fix `f`'s type from the first use. Diagnostic quality, not soundness.
- **The inspector's negations of generated relations** show the relation's internal name (`not next_id$ak()`, the
  aggregate's default), marked as part of `next_id`'s expansion; they are not yet unfolded into what they mean
  ("nothing to aggregate").
