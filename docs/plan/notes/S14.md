# S14: TodoMVC in the browser

Design: docs/design/BROWSER.md (decisions B1–B5, user 2026-10-05). Goal: show Blossom is general-purpose, Eve style.

## Plan

1. The host core, natively (`crates/blossom-web`): compile in memory, rounds through the engine, the page diff,
   persistence; a counter end to end in native tests. String functions.
2. In the browser: the wasm build, `web/host.js`, the page; the counter, then TodoMVC with the official CSS; the
   Playwright gate.
3. The `why` inspector.
4. The live editor.

## Progress
- **Slice 1, the host core** (`crates/blossom-web`): `compile` from sources in memory (the driver's
  `compile_with_loader`, with its analyses), an `App` that runs an event until its effects settle (a write takes
  effect the next round, so the host steps without events while the state changes, at most 1000 rounds), the page
  diff keyed by element id (`page.rs`), durable tables saved and restored as JSON with the runtime's schema hashes
  (`store.rs`), and the wasm-bindgen API (`wasm.rs`; the wasm build is 5.1 MB with the compiler). Inputs are listened
  to only when a rule reads them. Strings: `s.trim()`, `n.to_string()` (Appendix B; `++` and `len` were there).
  `examples/web/ui.bls` (the interface), `examples/web/counter.bls`; native tests drive both.
