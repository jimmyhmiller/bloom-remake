# S22 — the program split: what a page is given

The user (2026-10-07): "If we really wanted this to be production ready, we would need to do some code splitting on
what runs in the browser and what runs on the server, right?" Chosen (question tool): its own slice after S21.
Design: docs/design/CLIENTS.md §8.

## What was built

- **`ClientArtifact`** (`blossom-artifact::client`): the program projected onto one client role
  (`ValidatedProgram::project`, which existed since M-era but had only unit tests), its nodes and their roles in the
  projection's numbering, the surface columns kept; `encode`/`decode` (`BLSC`, format 1, postcard, the digest checked
  on decoding), `part` (the digest's first 16 bytes) and `leaks` (anything placed at another role).
- **The node serves it.** `blossom run --web` projects every client role at start, refuses a projection that leaks,
  serves it at `/blossom/client/ROLE` and makes `/blossom/app.json` itself (program, node, identity, link, clients):
  no source leaves the node.
- **`blossom build --deploy D --role R --out F`** writes the same bytes. The other `build` forms stay WP M6.3's
  (exit 7).
- **The handshake** carries the part (`Peer::Member.part`); a mismatch is `REJECT program`. The page reloads once on
  a stale-program refusal (30 s guard).
- **No compiler in a member page.** `blossom-web`'s `compiler` feature (default) holds `compile`; `load_client` reads
  an artifact without it. `scripts/build-web.sh` builds `web/pkg` (with) and `web/pkg-member` (without: 3.8 MB of
  wasm against 6.2 MB). `host.js` imports the module for its mode after asking for app.json.
- Refusals reach the page as data (`{reason, detail}`), not thrown strings.

## Fixed on the way

- **The IR projection could not project a real program.** It kept only types some kept item names by `TypeId`, but
  the validator derives expression types structurally (V8: "expression needs uninterned type Node(None)"). It now
  keeps every anonymous type over what it keeps; named types only where named.
- **`Program` did not round-trip through postcard.** `Persistence::Frame.guard` was `skip_serializing_if`, which a
  non-self-describing format cannot read back (it was there to keep digests of guard-free programs unchanged). It is
  serialized always now: every program's digest changed once. No checked-in file records one.

## Tests

- `client_artifact` (integration): the shared TodoMVC's `Browser` part holds the tab's rules and relations, both
  channels and the link events, none of the server's relations or rules, none of their names in the bytes; it
  round-trips; truncated, foreign and bit-flipped encodings are refused; `Server` is not a client role.
- `runtime_members`: a HELLO with another part is refused with `program`.
- `page_members`: both demos run from the served artifact; app.json holds no source.
- `tests/web/clients.spec.mjs`: the page fetched `/blossom/client/Browser` and `pkg-member`, no `.bls` and nothing of
  `pkg/`; a page open across a restart into a changed program is refused, loads again and shows the new program
  with its todos.

## New dependencies

None new to the workspace. blossom-artifact now uses serde, postcard and thiserror (workspace); recorded in
docs/design/DEPENDENCIES.md. blossom-cli no longer needs serde_json.
