# S17 — the small tier and the other timer kinds

The user chose (2026-10-06, from the list of easy placeholders): "Other timer kinds, The small tier". The small tier is
`blossom check`, `blossom explain`, scaling durations, `to_string` on every type and `blossom completions`.

## What was built

- **`blossom check FILE`** compiles the file's program and every spec in it that has a target (`spec S for M`), and
  prints each diagnostic once (a spec's target repeats its program's warnings). A program is checked on a deployment
  of its own (`api::compile_checking`: one node `n1` for a role-free program, else one node per role that holds
  nodes) unless `--nodes a,b=Role` gives one; `--spec S,T` checks only the specs named; `--strict` rejects warnings.
  Exit 0, 1, or 7 when a feature is not implemented. Every example checks except the two library modules
  (`e02_reliable_broadcast`, `e12_raft`: BLS0110, checked through the spec files that include them) and the three
  that use unimplemented features (e05, e06, e08: exit 7).
- **`blossom explain CODE`** prints the code's severity, its meaning and origin (from `blossom_base::codes`), and the
  paragraphs, list items, table rows and code lines of LANGUAGE.md that use it, each under its section. The `BLS`
  prefix is optional; with no code it lists every code. LANGUAGE.md is built into the binary.
- **Scaling durations**: `d * k`, `k * d` and `d / k` for an integer `k` of any type, truncating toward zero; out of
  range or `k = 0` is BLSR004, on the oracle and the engine (`Duration::times`, `Duration::divided_by`).
- **`to_string` on every type**: a value whose type has no library `to_string` is written as Blossom writes it
  (`printer::to_string_text`; IR `BuiltinFn::ToString { ty }`), so interpolation takes any hole. `value_text` became
  an exhaustive match: `Mod<N>` in decimal (a 256-bit `Display`), blobs, unknown variants, group values, bags,
  products and host values each have a form, with no `Debug` fallback.
- **`blossom completions SHELL`**: bash, zsh, fish, elvish and powershell scripts from the command tree
  (clap_complete).

- **Every kind of timer** (LANG-173): `every d times m`, `once after d`, `once` and the logical `every n ticks
  [times m]`, with `while G` on all but `once`. One firing rule, `blossom_ir::timers::Schedule`, serves both kinds of
  host: `TimerTable` (the node, the async cluster through the node, the browser), which is now asked once per tick,
  and the synchronous round loop (`blossom_sim::runtime::firings`), where every node runs a tick per round. A logical
  timer is due in every tick until it is spent (it keeps the node ticking, as its Dedalus expansion's staged counter
  would), so on a node its firings all come at the boot instant; a spent timer has no deadline. `blossom run` and
  `blossom deploy` warn of a logical timer (BLS1006, `api::deployed_lints`). The validator refuses an ill-formed
  `TimerDecl` (invariant 8, `Schedule::shape`). The browser host now asks its timers in every round, not only in
  timer-driven ones, so `once` fires in the start round and logical timers count every round.

## Decisions made on the way

- Logical timers run in the hosts, not as a rewrite into rules: a rule-derived `probe` would not be an event, so
  `on probe(…)` would not classify. `ConstructKind::LogicalTimer` (ARCHITECTURE, a rewrite expansion) stays unused.
- Under `times m`, firings a guard skipped count toward `m` (a count says where on the boot timeline a firing is);
  a guarded logical timer counts ticks while dormant. `once while G` is BLS0412: it could never fire.
- LANGUAGE §15.2 said LDFI refuses guarded timers; since HD item 4 only the stepped searches do. Corrected.

- A negative duration under a second printed without its sign (`0.007s` for `-7ms`): `printer::seconds` now works on
  the magnitude. Found by the `to_string` differential test.
- `to_string` of a node is its deployment name (`n1`), `node#3` when the evaluator was given none; the browser's one
  node is `app` on both the engine and the `why` oracle.
- The `to_string` text of a compound value is for reading, not an encoding: LANGUAGE Appendix B says so and points to
  `fingerprint` and codecs.
