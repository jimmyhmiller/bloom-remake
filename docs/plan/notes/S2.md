# S2 — the Blossom language on the same core

Slice 2 of docs/design/SLICES.md: `.bls` programs from source text through the Blossom frontend onto the IR that
slice 1 executes (the oracle, the synchronous simulator, provenance and LDFI), with Blossom specs driving `blossom sim`
and `blossom ldfi`.

## What was built

| Component | Where |
|---|---|
| The owned AST over the CST (items, relations and cells, handlers, views, bodies, statements, specs) | `blossom-front::ast` |
| Module loading: `use`/`import` files behind a `Loader` trait | `blossom-front::modules` |
| Resolution: scopes per module instance (instances renamed `a.r`), generics, value and relation parameters, choreography role binding and projection placement, interposition, roles and `at`, spec mode | `blossom-front::resolve` |
| The HIR | `blossom-front::hir` |
| Type checking: global union-find with deferred constraints, integer defaulting, `Node<R>` meets, lattice shapes, coercion sites for lifts, lattice methods, thresholds and arithmetic | `blossom-front::typeck` |
| Event/standing classification and the handler rules (BLS0504–0506) | `blossom-front::classify` |
| Lowering to the IR through `IrBuilder`: normative expansions (frame rules, handler headers, blocks, upsert staging, delta shadows, `not {}`/`forall` helpers, outer joins, `any`, aggregate views, invariants, lattice identity rules, `resolve` policies), lattice catalogues | `blossom-front::lower` |
| Specs: targets, scenarios (`nodes`, `assign`, facts, session ingress), trace relations and oracles, `faults`, checks | `blossom-front::spec` |
| The compile entry points and the Blossom artifact | `blossom-front::api`, `blossom-artifact::{bls, sim}` |
| Bloom^L's core lattices: join, order, lifts, `reveal!`, the operation catalogue with monotonicity classes | `blossom-lattice` |
| Lattice polarity (SEM-102), shared by both stratifiers | `blossom-ir::polarity` |
| Oracle: lattice-valued relations merged per key, lookups, lattice operations, collections, generators, `$prio`, session ingress and egress, `++`, `contains` | `blossom-oracle` |
| Simulation of Blossom programs and specs (tick 0 boot, physical timers on rounds, CR-20 frozen crashes, run seeds, sessions) | `blossom-sim::{bls, spec, runtime, sync}` |
| LDFI under the frozen view (`Alive` premises, frozen supports and appearance), lattice-cell lineage, session leaves | `blossom-ldfi` |
| Stratification (BLS0502 with its cycle) and `monotone` assertions (BLS0702) | `blossom-analysis::{strata, monotone}` |
| `blossom sim` and `blossom ldfi` for `.bls` programs and specs | `blossom-cli` |
| The corpus runner's Blossom backends and the S2 gate | `xtask corpus` (`corpus_bls.rs`, `S2_SUBSET`) |

Results: the S2 gate holds (`xtask corpus --gate` with `docs/plan/MILESTONE = S2`): every `core/` and `async/` case
whose features lie in the S2 subset passes; overall 86 `core`, 35 `async` and 25 `lattices` cases pass on the oracle,
none fails, and the `ldfi` area is unchanged (92 passing, the four known S1 exceptions). The examples:

| Spec | Verdict | Molly counterpart |
|---|---|---|
| `e02_specs.bls` RetryFaults 6/3/0 | holds (35 runs) | retry_deliv 6/3/0 (BENCH-130c) |
| `e02_specs.bls` RetryLongFaults 25/23/0 | holds (exhaustive, 2,183 states) | retry_deliv 25/23/0 (BENCH-130d) |
| `e02_specs.bls` RetryCrashFaults 4/2/1 | fails, `{C(A,2), O(A,B,1)}` | retry_deliv 4/2/1 (BENCH-130f) |
| `e02_specs.bls` OneShotFaults 4/2/0 | fails, one omission | simple_deliv 4/2/0 (BENCH-130b) |
| `e04_specs.bls` OmissionFaults 10/3/0 | holds (38 runs; exhaustive: 90 states) | 2pc 7/3/0 (BENCH-131a) |
| `e04_specs.bls` CrashFaults 10/3/1 | fails, `{C(C,4)}` | 2pc 6/3/1 (BENCH-131b) |
| `e10_specs.bls` SimpleLogFaults | fails, `{O(A,B,1)}` | simplog |
| `e10_specs.bls` AckRbFaults | holds | ack_rb |

`tests/integration/tests/bls_ldfi.rs` pins them and replays every counterexample.

## Deviations

The decisions of this slice are recorded in docs/DECISIONS.md, "Slice 2 decisions": CR-20 for Blossom specs, frozen
crashes in LDFI, `round`, deployments, the sim-artifact generalization, lattices (subset, catalogue names, role
erasure, polarity), `resolve` policies, run seeds, sessions in specs (and the `from s` grammar amendment in
LANGUAGE §3 and §17.2), the e04 changes (the `refuse` wiring, EOT 10), lattice lineage, the S2 gate, `monotone`
views, the node directory, `$self` typing, and the additive IR amendments (`set_persistence`, `set_construct_kind`,
`ConstructKind::Members`, covariant `assignable`, `count` over tuples, time arithmetic, session destinations,
`BuiltinFn::Concat`, `RelAttrs::monotone`).

## Follow-ups
- Constructs outside the S2 subset still report BLS0908: `choose!` and the other body filters (LANG-108), functions
  (LANG-180), sealed and soft tables, `final`, weighted collections, lattice folds, user-defined lattices, `Lex`,
  `LDom` and the other lattices, `monotone` handlers and modules, `index!`/`collect!`, `bootstrap fresh`. Slice 3
  needs `choose_most!`, `outer` and upsert under processes (e01).
- LDFI's lineage-driven search does not reach a verdict on e04 at 14/7/0 within 20,000 runs (exhaustive certification
  decides it in 523 states): the lattice-cell encoding (every contribution needed, any new one a hazard) is
  conservative, which widens the search.
- Lineage reports show generated relations (`tpc.apply_decision$when`) where a surface construct would read better.
