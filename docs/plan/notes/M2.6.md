# M2.6 — Durable byte storage

## What was built

`blossom-store` now has the filesystem trait and RealFs/SimFs implementations, deterministic volatile-write crash fates, injected I/O failures, an exclusive lock, atomic checksummed META, segmented CRC32C WAL framing and recovery, synced tick evidence, checkpoint installation and verification, and in-memory durability. The conformance suite exercises RealFs, SimFs, and memory WAL. The stable WAL recovery mirror and libFuzzer target use the same scanner. Required tests pass.

## Deviations

- The WAL segment header includes `lsn_base`. The specified header omits it, but without it recovery cannot verify the first record's absolute LSN after older segments are truncated: deriving the base from that very record would accept a corrupted LSN. The header's checksum covers this field.
- A successful WAL sync appends a reserved-kind record at `batch + 1` before the same fsync. The scanner does not emit this marker as user data. This lets the batch rule distinguish damage to the last acknowledged data record from a torn unacknowledged tail, including when no later user batch exists. `kind = 255` and `batch = u64::MAX` are reserved.
- `crash::enumerate_crash_points` takes explicitly captured syscall cuts with acknowledged prefixes and refuses an exploration bound that would omit combinations. Automatic cut capture and larger store workloads remain future work; M5.4 adds the store-level `xtask crashcheck` workloads.

## Follow-ups

- `DIST-020`: A media fault confined to the trailing sync marker is indistinguishable from a torn, unacknowledged marker under the §5.6 batch rule. It does not remove an acknowledged data record, but the stronger requirement that every media fault in any synced byte must be refused needs an independent durable sync receipt or a revised criterion. Reproducer: sync one record, flip a marker payload/CRC byte, then scan; the intact data record is recovered and the marker is treated as a torn tail.
- `DIST-020`: The bounded crash enumerator is currently driven by caller-supplied cuts; production crashcheck must capture every durable syscall of WAL/checkpoint workloads and include injected media faults. M5.4 owns the workload tooling.
