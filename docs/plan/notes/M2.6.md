# M2.6 — Durable byte storage

## What was built

`blossom-store` provides the filesystem trait and RealFs/SimFs implementations, deterministic volatile-write crash fates, injected I/O failures, an exclusive lock, atomic checksummed META, segmented CRC32C WAL framing and recovery, synced tick evidence, checkpoint installation and verification, and in-memory durability. The conformance suite exercises RealFs, SimFs, and memory WAL. The stable WAL recovery mirror and libFuzzer target use the same scanner.

`SimFs` automatically captures a deep state after every mutating Vfs call when crash recording is enabled. `crash::enumerate_crash_points` enumerates every such cut and every lost/surviving/sector-torn fate combination without sampling; an explicit bound fails closed. Its scripted WAL/checkpoint workload checked over 5,000 crash and media-fault images, verifying recovered prefixes, acknowledged records, checkpoint contents, and refusal after a bit flip in every acknowledged WAL, receipt, checkpoint manifest, `CURRENT`, or relation byte. Fate-vector length mismatches are errors, never defaulted.

## Deviations

- The WAL segment header includes `lsn_base`. The specified header omits it, but without it recovery cannot verify the first record's absolute LSN after older segments are truncated: deriving the base from that same record would accept a corrupted LSN. The header checksum covers this field.
- Each WAL sync first fsyncs data, then appends and fsyncs a reserved-kind batch marker, then atomically publishes a checksummed acknowledgement receipt (`.ack`: temp file fsync, rename, directory fsync). A successful `sync` returns only after all three steps. This ordered proof lets recovery reject media damage even in the last acknowledged data record or trailing marker, while a crash before acknowledgement may retain or lose an unacknowledged tail. This adds durability syscalls per batch compared with the single-fsync sketch in ARCHITECTURE §5.6; it preserves the committer's batch and poison invariants. `kind = 255` and `batch = u64::MAX` are reserved.
- Media faults to data that has passed the first fsync but has not yet acquired a durable receipt cannot be distinguished from an unacknowledged torn tail after a crash. That interval has no successful `WalWriter::sync` result and releases no tick. The crash checker tests the stronger actionable property for every acknowledged byte. Rejecting every media fault in that pre-ack interval would require an atomic cross-file persistence primitive unavailable in the specified Vfs crash model.
